## 2. 必须修改的地方

### 2.1 "自己搜到自己"不能整轮排除

按第 5 节的方案，只要这一轮调用过 `--kb-search`，这一轮的全部消息都不进索引。但最常见的用法恰恰是"之前那个问题怎么修的？照着修一下"：Agent 先搜，接着做一大段真正的排查和修改。按这个方案，这些真实的工作内容全都搜不到了，损失比"搜到自己"大得多。

**要求：**
- `--kb-search`、`--kb-show` 的调用和它们的结果**一律**不进索引（你说的识别方式和 marker 双保险保留）
- 这一轮里**除此之外没有别的工具调用**（纯问答轮）时，这一轮的用户提问和助手回答也不进索引
- 这一轮里**还有别的工具调用**（真正干了活）时，用户提问、助手回答和其他工具调用都照常索引
- `seq` 照旧给被跳过的消息占位，保证增量建和重建的结果一致
- 验收第 7 项按这个口径测：纯问答轮连续搜 3 次后，第 4 次的结果里不出现前 3 次的内容；再加一个"搜完之后接着改代码"的轮次，确认改代码的那部分**能**搜到

### 2.2 输出前脱敏

搜索结果会进入 Agent 的上下文，也就是会发给 Anthropic 或 OpenAI。而且是跨 Agent 的：在 Claude 会话里出现过的密钥，可能经由 Codex 的搜索发给 OpenAI。工具结果里常有 `Read` 读到的配置文件、`curl` 带的 Token。第 4 期整理时本来就要做脱敏，这期先把它做出来。

**要求：**
- 新文件 `kb/redact.rs`，第 4 期复用。至少覆盖：`password=` / `passwd` / `secret` / `token` / `api_key` 这类键值、`Authorization: Bearer …`、`sk-…`、`ghp_…`、`AKIA…`、JWT、`-----BEGIN … PRIVATE KEY-----` 块、URL 里的 `user:pass@`。替换成 `[REDACTED]`
- **在建索引时脱敏**：`messages.text` 里存的就是脱敏后的文本，FTS 也不收录这些值。`--kb-show --full` 读镜像原文时也要过一遍
- 单元测试覆盖上面每一类，并测一个"看起来像但不是"的反例（例如普通的 `token_count` 字段名不能被误伤）
- 脱敏会让"按 Token 值搜索"失效，这是预期行为，在 SKILL.md 和报告里不用特别说明
