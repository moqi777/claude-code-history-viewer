# 第 7.4 期报告：一块硬盘给多台电脑备份

版本 `0.7.4`（`mod.rs`、`branding.ts`）。打好的包：`src-tauri/target/release/bundle/macos/AgentKB.app`（ad-hoc 签名，`codesign --verify --deep --strict` 通过；主程序 `Contents/MacOS/AgentKB` SHA-256 `472b4fee3e87e58191f5619e19b2c51678e20882389d8f870fb789de9508404a`，61,659,760 字节）。**没有安装到 /Applications。**

## 1. 布局

设置里的备份文件夹（`<硬盘>/AgentKB-backup`）不变，里面每台电脑一个子文件夹 `<电脑名>-<id 前 8 位>/`，里面是原来的 `kb.db`、`kb.db.prev`、`raw/`、`notes/`，外加 `agentkb-backup.json`：

```json
{ "id": "…32 位十六进制", "name": "电脑名", "os": "macos", "first_backup_at": "…", "last_backup_at": "…", "sessions": 321, "app_version": "0.7.4" }
```

- **id**：第一次备份时随机生成（`uuid v4`），存在本机设置文件夹里的 `backup-device.json`（和 `config.json` 同一个文件夹，Mac 是 `~/Library/Application Support/agent-kb/`，Windows 是 `%APPDATA%\agent-kb\`）。没有放进 `config.json` 是因为界面保存设置时会整份回写，没有的字段会丢；也没有放进数据目录，因为数据目录可能被整个复制到别的电脑，身份不该跟着走。导出/导入（`.agentkb`）的设置里本来就不含它
- **改电脑名不换文件夹**：每次备份先扫配置文件夹下的子文件夹，找 `agentkb-backup.json` 里 id 等于本机 id 的；找到就用它，不看文件夹名。电脑名只在 json 里随每次备份刷新
- **文件夹名**：电脑名里的 `/ \ : * ? " < > |`、空白和控制字符换成 `-`，最多 40 个字符，去掉首尾的 `-` 和 `.`，空名字用 `computer`；这样在 exFAT / NTFS / APFS 上都合法
- `sessions` 是最近一次成功备份时库里的会话数，恢复时的列表用它显示，不用为了数数去拷每台电脑的 `kb.db`

## 2. 绝不写进别人的文件夹

`backup_dir::resolve` 每次备份都做：找不到本机的文件夹时，要建的那个名字如果已经存在且 json 里是别的 id → 报错 `…is the backup of another computer (名字 系统); nothing was written there`；写之前再读一遍 json，id 不等于本机 → 同样报错；`touch`（备份结束时刷新 json）也核对 id。出错时备份状态是 `error`，界面上"最近一次备份"显示这条错误，硬盘上什么都没写（测试里核对了文件夹里只有对方的 json）。

## 3. 旧布局（0.7.2/0.7.3）

配置文件夹下直接有 `kb.db` 或 `raw/`，并且**本机还没有自己的子文件夹**（即本机第一次用新版备份）时：把快照 `kb.db` 先拷到本机数据目录的临时文件，只读打开，读出 `files.source_path`；**全部**都在本机 Claude 或 Codex 源文件夹之下（路径统一斜杠，Windows 不分大小写）才把 `kb.db`、`kb.db.prev`、`raw/`、`notes/` 改名挪进本机子文件夹（先写好 json 再挪；中途失败就按相反顺序改回来）。以下情况都**不动**它，另建本机子文件夹，并记下"有旧备份"：有任何一行不在本机的源文件夹下（别的用户、别的系统的路径）、一行都没有、快照打不开、没有 `kb.db`。之后本机已有子文件夹，旧备份不再被判断或移动。

用 Mac 现在的真实硬盘（只读，`sqlite3 -readonly` 在拷到临时目录的副本上查）验证了判断：`/Volumes/Share/AgentKB-backup` 里是旧布局，321 行里 73 行在 `/Users/mo7/.claude/` 下、248 行在 `/Users/mo7/.codex/` 下，没有别的路径，所以装上 0.7.4 后第一次备份会把它挪进 Mac 自己的子文件夹。**我没有往那块硬盘写过任何东西。**

## 4. 恢复

新命令 `kb_restore_list(folder)`：选到的文件夹本身有 `kb.db` → 它自己算一份（有 json 显示电脑名，没有就是"旧版备份"）；另外列出里面每个有 json 且有 `kb.db` 的子文件夹，显示电脑名、系统、最近备份时间、会话数，本机的标"本机"。界面：只有一份就直接进入原来的检查和确认步骤；多份时先列出让用户点选，点哪份就检查哪份，仍然要再点"恢复"才开始；没有一份 → 提示这不是备份。直接选到某台的子文件夹、或旧布局的文件夹，都能恢复（`inspect`/`restore` 本身没改，仍然认含 `kb.db` 和 `raw/` 的文件夹）。

## 5. 设置页

"移动硬盘"那一栏下面显示"本机备份到：<实际文件夹>"（来自最近一次备份记在 `kb.db` 里的 `backup_folder`，随状态一起返回）；还没备份过显示"第一次备份时创建"；硬盘上留着没挪的旧备份时多一行说明（来自 `backup_old_layout`）。5 种语言都译了。

## 7. 测试

`backup_dir.rs` 10 个：id 只生成一次；文件夹名在各系统都合法；建文件夹+json、改名后找回同一个；两个 id 两个文件夹；别的 id 拒绝；旧布局属于本机 → 挪进去；别人的路径/部分不属于/空/打不开 → 原样不动；本机已有文件夹后不再碰旧备份；列表（各台、文件夹本身、旧布局）。

## 8. 需要知道的

- **已经在用 0.7.3 备份的 Mac 升级后**：第一次备份会把硬盘上的旧备份挪进 Mac 的子文件夹（一次 `rename`，很快，不重新拷）。Windows 第一次备份时看到根目录下已有旧布局但自己没有子文件夹，会判断它不属于 Windows（路径是 `/Users/...`），不动它，另建自己的子文件夹——所以 **先让 Mac 备份一次，再插到 Windows 上**，或者两个顺序都没问题，因为 Windows 不会碰它。
- 两台电脑同时往同一块盘备份没有额外加锁（每台只写自己的文件夹，不会冲突）。
- 子文件夹里的 `agentkb-backup.json` 被手工删掉后，那个文件夹就不再被认作本机的，下次备份会新建一个，旧的留在盘上不会被删。
- 同一台电脑重装系统（本机设置文件夹丢了）后 id 会重新生成，会得到一个新的子文件夹；旧的可以在恢复时看到并选择。
