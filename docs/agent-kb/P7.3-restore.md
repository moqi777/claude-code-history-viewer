# P7.3：从硬盘备份恢复（版本 0.7.3）

背景：`P7.2-restore-drill.md` 证明硬盘备份可以手动恢复。现在加一个按钮。用户决定：语义模型和索引不备份，恢复后重新下载模型、重建索引；设置不备份，恢复后重新走设置也行。

## 1. 界面

- 设置页"移动硬盘"那一栏加按钮"从硬盘恢复"
- 点了先让用户选备份文件夹，默认选已设置的硬盘上的 `AgentKB-backup`；换了电脑、还没设置硬盘时，也能自己挑文件夹
- 先检查备份，在页面里显示：会话数、笔记数、快照日期、原文大小；再说明"现在的数据会先挪到 `before-restore-<时间>` 文件夹，不会删除"。用户点确认后才开始。不要用 `window.confirm`
- 恢复中显示进度；完成后提示：语义搜索要重新下载模型、建索引（给按钮直达），并建议点一次"立即收集"
- 中英日韩繁简都要翻译，`i18n:validate` 通过

## 2. 后端

1. 检查备份：必须有 `kb.db` 和 `raw/`。`kb.db` 先拷到本机数据目录的临时位置再打开（硬盘上不用 SQLite 打开），跑 `integrity_check`。如果快照的结构版本比当前程序新，拒绝；比当前旧，按正常迁移升级
2. 拿到 `kb.lock`、`digest.lock`、`vectors/embed.lock`，保证恢复期间定时收集、整理、建索引都不会运行；拿不到就提示稍后再试，不要等
3. 把 `raw/`、`notes/` 拷到本机数据目录里的临时文件夹，跳过 exFAT 的 `._*` 文件，逐个核对大小和 SHA-256
4. 全部就绪后再替换：把现在的 `kb.db`（连同 `-wal`、`-shm`）、`raw/`、`notes/`、`vectors/` 改名挪进 `before-restore-<时间>/`，再把新的挪进来。`models/`、`logs/` 不动
5. 第 4 步之前任何一步失败，现在的数据完全不变，临时文件都删掉；第 4 步中途失败，要能把 `before-restore` 里的挪回去
6. 恢复后查一下：快照之后才追加到 `raw/` 的内容（快照每天一份，原文每次都追加），和数据库里记的文件位置对不对得上，下次收集会不会出错或重复。处理办法写进报告
7. 恢复后语义索引清空，状态显示"需要重建"

## 3. 测试

- 全部在临时 HOME 和临时文件夹里，不碰真实 `~/AgentKB` 和 `/Volumes/Share`
- 至少覆盖：正常恢复后能搜到、能打开；备份缺 `kb.db` 或损坏时拒绝且现有数据不变；拷到一半失败，现有数据不变、无残留；锁被占用时拒绝；第 4 步中途失败能挪回去；`._*` 文件被跳过；恢复后收集一次不出错、不重复
- 前端：确认前不会开始；完成后有重建索引的提示
