# P7.6：硬盘备份的几处收尾（版本 0.7.6，在 P7.5 之后做）

Windows 真机第 8 项（10-21）：0.7.4 在 Windows 上备份到 Share 盘成功（300 会话，`kb.db` 41 MB），但暴露了 4 个问题。

## 1. 备份目标是整块盘的根目录时，子文件夹散落在盘根

Windows 设置里目标是 `F:\`（不是 `F:\AgentKB-backup`），结果写成了 `F:\PC-20250506UOLZ-cff74fa7\`，和 Mac 的 `AgentKB-backup\mo7deMacBook-Pro.local-bc70cf56\` 不在一处；Mac 上点恢复只看 `AgentKB-backup`，看不到 Windows 那份。点盘按钮时前端会补 `AgentKB-backup`（`fields.tsx` 的 `DEFAULT_BACKUP_FOLDER`），所以多半是用"选择文件夹"选了盘根。

要求：
- 后端统一处理：目标是某个卷的根目录时，实际用 `<根>/AgentKB-backup`。保存设置时就改写，备份时再兜底一次
- 已经写在盘根的本机文件夹（`agentkb-backup.json` 的 id 是本机），下次备份时同盘改名挪进 `AgentKB-backup/`；不是本机的不动
- 恢复列表：选到盘根或 `AgentKB-backup` 时，两处的电脑文件夹都列出来

## 2. Windows 上盘名后面显示 `?\Volume`

`fields.tsx` 用 `v.uuid.slice(0, 8)`，Windows 的 uuid 是 `\\?\Volume{GUID}\`。改成显示 GUID 的前 8 位，两边一致。

## 3. "这个文件夹里已有 109 GB 备份"

目标是盘根时把整块盘的文件都算进去了。只统计 AgentKB 的备份内容（`AgentKB-backup` 下各电脑文件夹，或本机文件夹）。

## 4. 恢复别的电脑的备份时，提醒不够醒目

用户在 Windows 上点"从硬盘恢复"，直接进了 Mac 那份的确认页，只有一行路径能看出是 Mac 的。要求：确认页显著写出"这是另一台电脑（电脑名、系统）的备份，恢复后这台电脑的资料库会换成那台的"，只有一份备份时也一样；本机的备份标"本机"。

## 测试与交付

临时目录覆盖：盘根目标被改写、盘根旧文件夹挪进去且别人的不动、恢复列表两处都列、Windows 盘名显示、统计只算备份、别的电脑的确认页提醒。版本 0.7.6。7 项检查，打 Mac 包，写 `P7.6-report.md`，推送 `origin/agent-kb` 后停下，不安装。
