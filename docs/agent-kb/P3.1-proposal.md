# P3.1 提案：`--kb-search` 输出瘦身（待 leader 评审）

来源：用户在真机上用 Codex 调用 agentkb 技能查「windowserve 之前有段时间很大」，一次搜索 + 两次上下文读取就找到了答案和 resume 命令，但 Codex 反馈输出里有大量重复和噪音。本文把反馈整理成需求，并对照了当前代码（`src-tauri/src/kb/search.rs`）。**尚未动任何代码。**

## 需求

### R1 标题截断（高收益，低成本）
- 现状：`title` 只做脱敏，不截断（`search.rs` 约 685、993 行）。用户第一句话很长时整段进标题（实测约 3 KB）。
- 要求：CLI 输出的 `title` 截到约 60 字，超出加 `…`。只改输出；库里存的标题和 GUI 显示不动。
- 验收：构造 3 KB 标题的会话，搜索输出里 `title` ≤ 61 字符。

### R2 子会话合并到父会话（高收益，中成本）
- 现状：子会话默认纳入（分数 ×0.8），占掉 5 个名额里的 2 个，snippet 与父会话重复。
- 要求：
  - 命中子会话时合并到父会话条目下，只给计数（如 `subagent_hits: N`）。
  - 父会话自身没命中、只有子会话命中时，仍显示父会话，并带子会话的最佳 snippet。
  - `--include-subagents` 保留，作为展开成独立条目的开关。
- 验收：同一父会话加 2 个子会话命中时，`--limit 5` 得到 5 个不同的父会话。
- 待评审：分组发生在 SQL 取数之前还是之后（影响 `--limit` 语义）；GUI 默认已排除子会话，是否沿用同一路径。

### R3 默认精简输出，`--verbose` 恢复全部（中收益，低成本）
- 默认去掉 `paths.mirror/original`、`highlights` 偏移量、`tokens` 数组（对模型无用，技能说明也禁止直接读这些路径）。
- 默认保留 `session_id`、`title`、日期、项目、`snippet`、resume 命令、`read_mode`。
- 只改 CLI 序列化层；GUI 走 `kb_search` Tauri 命令，仍需要 `highlights`，不改内部结构。
- `SKILL.md` 模板随之更新，使已安装的技能显示「需要更新」。

### R4 snippet 按角色放宽（中收益，低成本）
- 现状：窗口为命中前 60 字、后 140 字（`SNIPPET_BEFORE/AFTER`），命中在助手回答里时常断在结论前。
- 要求：命中 assistant 消息时改为前 60、后约 300 字；用户消息不变。
- 验收：用 `P3-eval.md` 中答案在回答里的题，snippet 能带出结论句。

## 附带
- 「只搜 WindowServer 内存能否一次搜中」属于检索覆盖问题：建议在 `P3-eval.md` 新增一组题，只记录结果，不调排序。
- 改完用同一批真实问题重跑，报告里给出前后输出字节数对比。

## 需要 leader 决定
1. 是否立项为 P3.1，范围是否就是 R1–R4。
2. R2 的分组语义（见上「待评审」）。
3. R3 的默认精简是否会影响已安装技能的兼容（旧版 SKILL.md 若依赖被删字段）。
4. 验收标准是否沿用 P3 的性能线（查询 < 300 ms）。
