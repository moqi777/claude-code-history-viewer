# 第 6.2 期报告：搜索框不再边打边搜

版本 `0.6.2`（Rust `kb/mod.rs`、前端 `branding.ts`、`fixtures.ts`、`KbHome.test.tsx` 四处）。打好的包：`src-tauri/target/release/bundle/macos/AgentKB.app`（本地 ad-hoc 签名，`codesign --verify --deep --strict` 通过；主程序 SHA-256 `9f7f911fe5144006668a910a8449ddcfba0f32a63becdd607f605ecc6ff7b666`，61,378,032 字节）。**没有安装到 /Applications**（那里还是 0.6.0）。

## 1. 原因

`SearchBox` 的 `onChange` 每次都写 store，停 300 ms 就 `runSearch`，没有看输入法的组字状态。拼音还没选字时，输入框里是 `s u do` 这样的半截内容，搜索就拿它去搜，结果里才会高亮单个字母。语义搜索开着时每次搜索还要加载一次模型，边打边搜就反复加载。笔记页的搜索框（`KbNotes.tsx`）是同一种写法。

## 2. 方案（按第 2 节）

- **只在回车或点"搜索"按钮时搜**，会话搜索和笔记搜索都是。打字过程中不搜，去掉了 300 ms 防抖。
- **组字中的回车不算**：新文件 `kb/searchKeys.ts` 的 `isSearchEnter`，要求 `key === "Enter"`、`nativeEvent.isComposing` 为假、`keyCode !== 229`。Esc 在组字中也不清空（组字时 Esc 是取消组字）。两处输入框共用。
- **按钮**：输入框右边新加；输入框为空时禁用；搜索中显示转圈和"搜索中…"（用已有的 `kb.search.searching`）。新键 `kb.search.button`（en 搜索 "Search"、ko 검색、ja 検索、zh-CN 搜索、zh-TW 搜尋），5 种语言都加了。原来输入框右侧的转圈去掉了（改在按钮上），✕ 始终在有文字时显示。
- **搜索中再搜，以最新的为准**：`searchEpoch` 本来是对的（每次 `runSearch` 加一，返回后不等于当前值就丢弃；清空也会加一），新增测试证明了连续两次时先发后到的结果不覆盖后发的。
- **搜索期间可以继续打字，输入框不重挂载**：查出一处真问题——结果回来时 `runSearch` 用发起时的 `query` 写回 store，会把用户这时新打的字**改回旧值**。已改成写回时读当前输入框里的内容。测试：搜索进行中把 `死锁` 接着打成 `死锁 redis`，结果回来后框里仍是 `死锁 redis`，且 DOM 节点没换。
- **清空**：✕ 和 Esc 不变，同时清空结果回到默认列表。
- **"是否在搜索"的判断**：原来用"框里有字"决定显示结果区，现在没按回车就打字会出现一个空框。改成看 `search.status !== "idle"`（`KbHome.tsx`）；过滤条件变化后重新搜索也同样只在已经搜过时才触发（`useKbStore.setFilters`）。它重搜时用的是框里当前的字。
- 笔记页：`query`（框里的字）和 `submitted`（上次搜的）分开；重复搜同一句也会重新加载。

`--kb-search` 键名、排序、结果内容都没动（只改了前端和版本号）。

## 3. 标题半透明

不是被反复刷新，是悬停样式。`ResultCard` 的标题按钮写的是 `hover:text-accent-foreground`，而 `--accent-foreground` 在浅色主题里是 `oklch(0.98 0 0)`（近乎白色，`index.css:109`），鼠标一停在那条结果上，标题就变成白底上的近白字，看着像半透明；深色主题里反过来（`0.12` 的深字配深底）。代码里这个组件没有任何 `opacity`，`aria-busy` 也没有样式。已改为 `hover:text-accent`（主题色）。该类名在 `kb/` 里只此一处。

这是从代码和颜色值推出来的，我没有在真机上复现截图；用户装上后把鼠标停在结果标题上看一下即可确认。

## 4. App 里一次语义搜索的耗时

`kb_search` 在 App 里调用的就是命令行 `--kb-search` 同一个 `search::search`，向量那一步 `prepare` 是同一个函数，所以用命令行量；没有开 GUI 量（GUI 多一次 IPC 往返，相对这里的数字可以忽略）。在新拷的快照上（24,526 段向量，bge-m3 int8），临时在 `prepare_with` 里加了计时输出，量完已还原，不在提交里。同一句"插着的U盘弹不出来怎么办"连搜 6 次：

| 阶段 | 耗时 |
|---|---|
| 打开向量库并读入矩阵 | 12 ms |
| **加载模型（建 ONNX 会话）** | **472–485 ms** |
| 算查询向量 | 10–14 ms |
| 向量打分（24,526 段） | 12 ms |
| 其余（关键词搜索、合并、进程启动） | ≈ 230 ms |
| **总共（热缓存，5 次）** | **0.74–0.75 秒** |

第一次（刚拷出来的模型文件，系统缓存是冷的）**3.38 秒**。也就是说：热的时候一次搜索约 0.75 秒，其中约 2/3 是加载模型，计算本身只有 20–30 ms；**冷的第一次超过 1.5 秒**。不再边打边搜后，每次回车约 0.75 秒，在线内；超线的只有"很久没用、模型文件已被系统挤出缓存"之后的第一次。

**办法（由 leader 决定，我没有做）**：
1. 保持现状。热的 0.75 秒，冷的第一次 3 秒多，只发生在第一次。
2. 用户第一次聚焦搜索框时，在后台线程先把模型会话建好并留在内存里（约 2 GB 常驻），之后每次搜索只剩 ≈ 0.25 秒。代价是 App 常驻 2 GB，P6 报告第 7 节已说过这个顾虑，所以不建议默认这么做。
3. 聚焦搜索框时只在后台把模型文件读一遍（预热系统缓存，不常驻），消除冷的第一次，热的耗时不变。几乎没有代价，是我倾向的办法，但要改后端，这期没做。

## 5. 测试

前端新增或改写（`KbSearch.test.tsx`、`KbNotes.test.tsx`）：
- 打字过程中（连打 `s`、`su`、`s u do`，等 5 秒）不调用搜索，仍显示默认列表
- 回车调用一次
- 组字中回车（`isComposing` 为真、`keyCode` 229）不调用，之后一次真回车才调用
- 点按钮调用一次；输入框为空时按钮禁用
- 搜索中按钮显示"搜索中"，输入框同一个节点、接着打的字不丢
- 连续两次搜索，先发后到的结果不覆盖后发的
- Esc 清空输入框和结果；✕ 清空（原有测试）
- 笔记页：打字 400 毫秒不调用，组字回车不调用，回车和按钮调用

原有测试里"停下来 300 ms 就搜"的用例改成了按回车。

## 7. 真机确认（用户做）

1. 用拼音输入法连续打一句话：不被打断，结果区不闪。
2. 按回车，或点"搜索"：出结果。
3. 拼音里夹英文（组字中按回车上屏）：这一下回车不触发搜索；再按一次才搜。
4. 把鼠标停在结果标题上：标题变蓝，不再发白。
