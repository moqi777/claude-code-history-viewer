## 2. 必须先修：Codex 把旧会话压缩成 `.jsonl.zst`

我在真实库上核对过（只读）：`files` 表里 Codex 有 214 个 `deleted` 的 `.jsonl` 和 214 个 `present` 的 `.jsonl.zst`，同一批会话。两边各索引了 59,200 条消息，所以**现在 Codex 的每条搜索结果都会出现两次**，其中一个的 resume 显示"不可用"。原始备份两份都在，没有丢。

**要求：**
- **认人不认名字**：源文件 `X.jsonl` 不见了，同时出现 `X.jsonl.zst`（或者反过来），并且解压后的内容开头和原来的镜像一致，就当成**同一个文件换了存储方式**：更新 `source_path`，`source_status` 保持 `present`，不算删除，不当新会话。Claude 那边以后如果也这样做，同一套规则也要能用
- **修好已有的数据**：升级后第一次同步时，把这 214 对合并成一个会话：同一个会话 id 只留一条，消息只索引一份，resume 可用。**raw 里的两份镜像都保留，不删**（raw 是唯一可信来源）。合并前先备份 `kb.db`
- **测试**：在临时 HOME 里复现（先收集 `.jsonl`，再换成 `.zst`，再同步），断言：会话数不变、没有"源已删除"、搜索不重复、raw 里两份都在；另外测一个**内容不一致**的 `.zst`，要按新文件处理，不能合并
- **验收（真实库）**：装好新版、同步一次后，`files` 里没有 `deleted` 的 Codex 文件（除非真被删了），`sessions` 里没有重复的会话 id，首页没有这 214 个"已删除"徽章
