# 7.2 期：exFAT 移动硬盘上数据库快照失败 + 界面版本号

> 先读 `P2-design.md` 的移动硬盘备份部分和 `backup.rs`。改的是 Mac/Windows 共用代码。版本 `AGENTKB_VERSION = 0.7.2`。

## 1. 现象（leader 在用户 Mac 上复现，2026-10-19）

- 移动硬盘 `/Volumes/Share`：exFAT、USB、macOS 用 fskit 挂载
- 每次备份：`raw/` 341 个文件、`notes/` 都复制成功，只有数据库快照失败：
  `cannot finalise /Volumes/Share/AgentKB-backup/kb.db.tmp-<pid>: attempt to write a readonly database`
- 用 `--kb-backup` 稳定复现。失败在 `online_backup` 里备份完、`journal_mode=DELETE` 那一步
- 对照：系统自带的 sqlite（Python）在同一块盘上做同样的步骤能成功；在盘上新建普通数据库也能成功。推测是打包进来的 SQLite 在这块盘上用 WAL 共享内存（`-shm`）时失败

## 2. 要改的

1. **快照先在本机生成，再整份拷到硬盘**：在数据目录里的临时位置用 `online_backup` 生成，切成 `DELETE`、本机跑 `integrity_check`，然后用 `fsutil::copy_atomic` 拷到硬盘，拷完对比 SHA-256，最后再轮换 `kb.db` / `kb.db.prev`。硬盘上不再打开 SQLite 写东西。本机临时文件在成功和失败时都要删掉
2. **测试**：单元测试覆盖新流程（成功、拷到一半失败、校验不一致时都不覆盖旧快照）；Mac 上用 `hdiutil` 建一个 **exFAT** 磁盘镜像做真机集成测试（P2 已有 hdiutil 测试，可参照），修之前失败、修之后通过
3. **界面版本号**：`src/kb/branding.ts` 写死了 `AGENTKB_VERSION = "0.6.4"`，用户 0.7.1 的界面左下角还显示 0.6.4。改成从后端拿（状态里已有 `agentkb_version`），或者加一条测试保证它和 `src-tauri/src/kb/mod.rs` 的值一致，以后升版本不会漏

## 3. 验收

- 7 项检查；打包；写 `P7.2-report.md`，推送 `origin/agent-kb` 后停下，不要安装到 /Applications
- 安装后由 leader 在用户真实硬盘上点一次"立即备份"确认
