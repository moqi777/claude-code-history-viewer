# 第 5 期：一键导出 / 导入，搬到另一台电脑

> 先读 `PLAN.md`、`P4-acceptance.md`、`P4.1-acceptance.md`。PLAN 第 3 节的架构决定、第 6 节的通用约束都适用。
> 遇到 **【检查点】** 必须停下，把产出交给用户转给 leader 审核，通过后才能继续。
> 版本 `AGENTKB_VERSION = 0.5.0`。

## 1. 本期目标

做完后，用户能：

1. 在 App 里点"导出"，把整个知识库（原始备份、笔记、索引、设置）打成**一个文件**，放到移动硬盘、网盘或者直接拷到另一台电脑
2. 在另一台 Mac 上装好 AgentKB，在向导第一页或设置里点"从文件导入"，导入后会话数、笔记数、搜索结果和原来那台**完全一致**
3. 新电脑上已经用了一段时间、有自己的数据时，也能把导入的数据**合并**进去，两边的都不丢

PLAN 第 4 节的验收标准：新设备导入后会话数、笔记数、搜索结果与原设备一致。

## 2. 范围

**要做：** 导出、导入（导入到空库、合并到已有库）、校验、中途失败不伤数据、App 里的入口和进度、`--kb-export`/`--kb-import` 命令、第 0 步的小修。

**不做：** 两台电脑之间持续同步（只做一次性搬家）；把会话写回新电脑的 `~/.claude`、`~/.codex`（PLAN 第 3 节第 6 条，仍然只读）；Windows（第 7 期，但文件格式要为它做好准备）。

## 3. leader 已定的事

| 项 | 决定 |
|---|---|
| 一个文件 | 导出成单个文件，扩展名 `.agentkb`。里面有一份清单（manifest）：格式版本、导出时间、来源机器的 AgentKB 版本和 schema 版本、每个文件的大小和 SHA-256、会话数、笔记数 |
| 带哪些东西 | `raw/` 和 `notes/` 必须全带（这两个是可信来源，丢了无法再生）；`kb.db` 也带上，用 `VACUUM INTO` 导出一份紧凑的快照（顺便去掉现在约 100 MB 的空闲页），导入时 schema 版本一样就直接用，省掉重建的时间；不一样就从 `raw/` 和 `notes/` 重建。`logs/`、旧的 `kb.db.*` 备份、`digest-work/` **不带** |
| 设置带哪些 | 只带和机器无关的：排除规则、每日整理的参数、收集频率。**不带**：数据目录路径、移动硬盘的卷信息、`cli_path`、定时任务。导入后 `digest.enabled` 一律设为 `false`，要用户在新电脑上点"测试"通过后自己打开（新电脑的登录、额度都不一样） |
| 路径 | 文件里一律用相对路径和 `/`，不依赖 Unix 权限位，为第 7 期 Windows 导入做准备。`files.source_path` 这类绝对路径，导入时如果用户名或者家目录不同，要按家目录换算（`/Users/a/.claude/...` → `/Users/b/.claude/...`），换算不了的保持原样 |
| 来自另一台设备的会话 | 新电脑的 `~/.claude`、`~/.codex` 里没有这些会话的源文件。它们**不能**显示成"源文件已删除"（那是用户在这台电脑上删的意思），要有单独的状态，界面上显示"来自另一台设备"。`resume.available` 为 false，提示用 `--kb-show` 看备份。如果新电脑上后来也出现了同一个源文件（比如用户自己把 `~/.claude` 也拷过去了），收集时正常认回来 |
| 合并规则 | 两边都有同一个会话（`source` + `session_id` 一样）：内容是同一份的前缀关系（一个是另一个的开头），留长的；内容对不上，**两份都留**，参照 P2 备份冲突的做法。笔记：同一个会话两边都有笔记，留整理时间更新的，另一份存到 `notes/.conflict-*`。一律不删用户已有的任何文件 |
| 原子性 | 先在临时目录里解开、逐个校验 SHA-256，全部通过后才切换（参考 `migrate_dir.rs` 换数据目录的做法）。任何一步失败，原来的数据一个字节都不能变。导入前先备份现有的 `kb.db` |
| 导出时的一致性 | 导出期间拿住收集锁和整理锁，或者用快照，保证导出的 `raw/`、`notes/`、`kb.db` 是同一时刻的。整理正在跑时提示"正在整理，等它完成后再导出"，不要中途打断 |
| 敏感内容 | `raw/` 是原文，**没有脱敏**，里面可能有密码、Token。导出文件和数据目录一样敏感。导出界面要明确提示；文件权限只给当前用户。要不要支持"设密码加密"，你在设计里评估（用哪个库、性能、密码忘了怎么办），给出建议，由 leader 定 |
| 压缩 | 用已经在用的 `zstd`。在设计里用真实数据量出导出文件的大小和导出、导入的耗时 |

## 4. 执行步骤

### 步骤 0：小修

`P4.1-acceptance.md` 第 5 节：只有 App 版本变了时，不再提示"技能需要更新"。只看 `TEMPLATE_VERSION` 和程序路径。

### 步骤 1：写设计说明 `docs/agent-kb/P5-design.md` 【检查点】

每一条都写出依据的文件和函数：

1. **文件格式**：`.agentkb` 里面的结构、manifest 的完整示例、格式版本以后怎么升级；用什么打包（tar + zstd 还是别的），为什么
2. **导出流程**：锁和快照怎么做；`VACUUM INTO`；大文件怎么流式写，不一次读进内存；进度怎么报；中途取消怎么处理
3. **导入流程**：空库导入和合并导入分别走一遍；校验、临时目录、切换、失败回滚；schema 版本不同怎么办；导入后要不要立刻同步一次
4. **路径换算**和"来自另一台设备"的状态：表结构要不要改，`--kb-search`、`--kb-show`、首页怎么显示
5. **合并规则**：用具体例子写出每种情况的结果（只有一边有、两边一样、一边是另一边的开头、两边对不上、笔记冲突、排除规则冲突）
6. **用真实数据量出来的数字**：在临时 HOME 里，对真实库的副本导出、再导入，给出文件大小、导出耗时、导入耗时（直接用 `kb.db` 和重建索引两种情况）
7. **加密**：要不要做、怎么做，给出建议
8. **界面草图**：设置页的导出、导入；向导第一页的"从另一台设备导入"；进度、出错提示
9. **改动清单和新依赖**

写完提交并推送，然后**停下**，等待审核。

### 步骤 2：实现

按设计实现导出、导入、合并、界面和命令。

- 前端测试：导出、导入的入口、进度、出错提示

## 5. 验收标准

**执行 AI 自己验证（报告里贴命令和输出，全部在临时 HOME 里）：**

1. **一致性**：真实库副本导出，导入到另一个临时 HOME（用户名不同），会话数、笔记数一样；`P3-eval.md` 的 15 道题加"电池 耗电"，两边 `--kb-search` 的结果（会话 id 和顺序）一样，`--kb-show` 能读到同样的内容
2. **完整性**：导入后 `raw/`、`notes/` 里每个文件的 SHA-256 都和原来一样
3. **防损坏**：把导出文件改掉一个字节再导入 → 拒绝导入，给出明确提示，原来的数据没有任何变化
4. **防中断**：导入到一半杀掉进程 → 原来的数据没有任何变化，再导入一次能成功
5. **合并**：两个各有数据的库合并，第 3 节的每种情况结果符合规则，任何一边原有的文件都没被删
6. **导出时不出错**：导出进行中定时收集照常完成；整理正在跑时导出会给出提示
7. **设置**：导入后排除规则还在、生效；`digest.enabled` 是 `false`；数据目录、移动硬盘、`cli_path` 是新电脑自己的
8. **不碰源目录**：导出、导入前后对 `~/.claude`、`~/.codex` 拍快照对比，没有变化
9. 一次 `--kb-search` 仍然 ≤ 300ms；PLAN 第 6 节的全部检查通过；写好 `docs/agent-kb/P5-report.md`，推送到 `origin/agent-kb`

**用户真机确认（报告最后单独列出清单）：**

10. 在 App 里导出一次，看到文件大小、用时，文件能打开（manifest 能读出会话数）
11. 如果有第二台 Mac：装好 AgentKB，从文件导入，搜一个记得的问题，结果和原来那台一样（没有第二台就跳过，由第 1 项覆盖）

## 6. 注意

- 用户的 `~/AgentKB` 里有真实数据。导出只读它（拿锁的时间要短）；**导入只在临时 HOME 里测**，不要往真实的 `~/AgentKB` 导入任何东西
- 导出的测试文件里有用户的原始会话，不要提交进仓库，测试完删掉，报告里写明删了
- 遇到本文件没有覆盖、而且会影响设计的情况，先停下来提问
