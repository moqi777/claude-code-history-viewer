## 2. 为什么：看到了两件事

### 2.1 向量一路：超大会话每次都挤进前 10

向量一路给会话打的分是"最像的那一段 + 0.25 × 第二像的那一段"。会话里的段越多，"总有一段碰巧像"的机会越大。真实库里每个会话的向量段数（取上面 70 道题导出的 247 个会话）：中位数 18，前 10% 以上 264，最多 **2241**。口语长句本身也像随口一句，会话里那些短的口语段（"不行啊，把你给我的模块导进去后 还是不行""你怎么不动了呀？"）跟任何口语问句的相似度都偏高。

70 道题（本期 8 + P6 的 31 题各两种问法）里，向量前 10 出现次数最多的会话：

| 会话 | 向量段数 | 出现在向量前 10 的题数（共 70） | 其中 8 道口语题 |
|---|---|---|---|
| `15bf7c02`（地图选点进阶功能） | 2241 | **24** | 6 |
| `c8b03ea5` | 1314 | **19** | 6 |
| `01a0cc1c` | 512 | 15 | 5 |
| `01a09ea0` | 717 | 12 | 3 |
| `019ed9cc` | 596 | 11 | 3 |
| `019fda74` | 1977 | 11 | 1 |

这几个会话和问题没有关系。第 1 题里 `c8b03ea5` 命中的那一段是"先点『取消』，别点重置"（讲小火箭 VPN），第 2 题里是一张 token 表格。

### 2.2 关键词一路：口语长句退回"任一词命中"，常见词一起抬

整句交给关键词一路时，所有词不会同时出现在一条消息里，于是退回"任一词命中"（权重 0.5）。分词后的词在库里的覆盖面（出现在多少比例的会话里，`kb.db` 只读副本数的）：

| 句子里的词 | 会话占比 | | 句子里的词 | 会话占比 |
|---|---|---|---|---|
| 不 | 84.6% | | 终端 | 20.1% |
| 文件 | 75.8% | | 件夹/文件夹 | 9.9% |
| 再 | 79.5% | | 扫码 | 5.9% |
| 看 | 69.6% | | 月付 | 6.2% |
| 项目 | 63.0% | | 就断 | 1.8% |
| 打开 | 41.0% | | 弹个 | 0.7% |
| 固定 | 42.1% | | 烫得 | 0.4% |
| 每次 | 31.1% | | | |

"不""再""看""文件""打开""固定"一半以上的会话里都有。一个很长的会话里总有几条消息碰到这些词，关键词一路就把它排在前面；它又恰好在向量前 10 里，两路都有，得到"关键词+语义"的加成。每个口语题的前 5 里都是同几个会话（`c4c081c6`、`c8b03ea5`、`15bf7c02`、`01a0cc1c`、`019ed9cc`），不论问的是什么。

## 3. 修法

三处。先说下面的数是怎么来的，因为 P6 的审核提醒过"别为测试集调常数"。

### 3.1 向量一路：按会话大小校正（主要的一处）

会话的向量分改为：`best + 0.25 × second − 0.025 × ln(会话的向量段数)`。

**依据（没用期望会话）**：对 70 个问题、全部 265 个有向量的会话，各自做"会话分对 ln(段数)"的回归，斜率平均 **0.0336**（最小 0.0251、最大 0.0419，逐题见 `p61/slope.txt`）。也就是说，不管问什么，段数每大一个量级（×e），分数平均高 0.034——这是"总有一段碰巧像"的纯规模效应。**取了 0.025（约四分之三）**：不全扣，因为大会话里确实有更多真相关的内容；也让 P6 的"新 15 题整句 ≥14"留余量（0.035 以上整句会掉到 13）。

**对其余的 62 道题没有拖累**：用重放（见 §5）算，新 15 题整句 15/15、关键词形 11/15（现 14、10），旧 16 题两种问法都不低于现在。

### 3.2 向量一路：`MARGIN` 0.1 → 0.25

"只留离第一名不超过 0.1 的会话"。校正以后，第一名和后面的差距变小，0.1 会把真正相关的第 5–10 名也切掉（第 1 题的 `019ec017` 校正后 0.659，第一名 0.832，差 0.17，被切）。0.2 以上就是一片平台：0.2、0.25、0.3、不设上限，整个 70 题的结果**完全一样**（§5 表 3），所以选 0.25，不是在某个点上凑出来的。`TOP_SESSIONS` 仍是 10，`RRF_K`、`W_KEYWORD_ANY`、`SECOND_WEIGHT` 都不动。

### 3.3 关键词一路：常见词闸门

规则（只在**混合合并**里用；语义关或没建索引时，关键词结果和 0.6.0 一模一样）：

1. 句子里 ≥ 4 个词才启用；"电池 耗电""tedis 依赖"这类短关键词查询**整个绕过**，行为不变。
2. 一个词出现在 ≥ **30%** 的会话里算常见词。会话数用 `messages_fts` 的 `MATCH` 计数，每个词一条查询，几毫秒。
3. 一个会话的关键词命中，如果命中的消息里**一个非常见词都没有**，就不进合并的那份关键词列表（不算有效命中、不拿"关键词+语义"的加成）；它仍然留在结果尾部，标 `keyword`，所以不会丢结果。

**依据与限制，说实话**：这一处在 70 题上的作用是**中性**，不是主力（§5 表 4：θ=30% 和 40% 时与不加完全一样，只有第 5 题从 2 变 3）。θ 取 15%、20% 反而会误伤（新题整句 15→14、关键词形 11→10、旧题 15→14），把真命中的会话也筛掉了。另外试过一种改法——**把常见词从关键词句子里整个删掉再搜**（`p61/trim_experiment.py`，`trim_experiment.out`，用真实 `--kb-search`）：θ=15/20/30/40 时口语题都停在 3/8，新题整句掉到 12–13、关键词形最低 8，旧题整句掉到 14–15，没有一档比现在好。

那为什么还加？因为任务要求写明"只靠常见词命中不能算有效命中、不能拿加成"，而 §3.1 只让超大会话离开向量前 10，一个**中等大小**的会话只靠"怎么""打开"在关键词那边抬高、同时碰巧在向量里，仍会拿到加成。闸门挡的是这种情况。如果 leader 觉得多余，可以去掉，主效果不受影响。

**没有选的做法**：

- **扩充停用词表**（"每次""打开""固定"也进去）：这些词在别的问题里是实词（"每次开机""固定链接"），按语感写死会误伤；按库的覆盖率算，在另一个人的库里自己适应。
- **逐个 chunk 的"枢纽度"校正（CSLS）**：理论上更准，要给向量文件加一列、建完索引后补算，是大改动，不是小修。如果保密口语题证明 §3.1 不够，再上这个。

## 5. 预测（重放）

`p61/sim61.py` 不需要二进制和模型：读 `vecall.jsonl`（70 个问题的向量会话分和每个词的会话占比，用 `diag61.rs.txt` 里的临时测试在副本上导出）和 `gate.jsonl`（关键词一路的结果和闸门后的结果），按 `rank.rs` 的 RRF 重放。**基线重放与真实 `--kb-search` 的名次一致**（口语题 `[0,9,0,0,4,2,11,4]`；新题整句 14/15、关键词形 10/15）。重放里没有笔记优先，所以旧 16 题读出来是 15/16（真实是 16/16，其中一题靠笔记优先）。完整输出 `p61/sim61.out`。
