# 第 7.2 期报告：exFAT 移动硬盘上数据库快照失败 + 界面版本号

版本 `0.7.2`（`mod.rs` 和 `branding.ts`）。打好的包：`src-tauri/target/release/bundle/macos/AgentKB.app`（ad-hoc 签名，`codesign --verify --deep --strict` 通过；主程序 `Contents/MacOS/AgentKB` SHA-256 `e858aa56fb609c4588043e4265ea78ffa5f3e1c03137ff53a6199143ec98c738`，61,463,472 字节）。**没有安装到 /Applications**。

## 1. 改了什么

`backup.rs::snapshot_db` 不再在硬盘上打开 SQLite，新流程（`place_snapshot`）：

1. 在数据目录里用 `online_backup` 生成 `kb.db.snapshot-<pid>`（切成 `DELETE`），本机跑 `integrity_check`
2. `fsutil::copy_atomic` 拷到硬盘上的 `kb.db.new-<pid>`
3. 本机文件和硬盘文件比 SHA-256，不一致就报错
4. 通过后才把 `kb.db` 轮换成 `kb.db.prev`，再把新文件改名为 `kb.db`
5. 成功和失败都会删掉本机临时文件和硬盘上的 `.new-*`

任何一步失败，硬盘上原来的 `kb.db` / `kb.db.prev` 不动。`online_backup` 本身没改（`import`、`migrate_dir` 也在用）。

界面版本号：`branding.ts` 仍是常量，改为 0.7.2，新增 `src/kb/branding.test.ts`，读 `src-tauri/src/kb/mod.rs` 里的 `AGENTKB_VERSION`，两边不一致测试就失败（我先改了常量之前跑过一次，确实红）。选测试而不是从后端取，是因为左下角状态栏（`AppLayout.tsx`）拿不到 overview。`fixtures.ts` 和 `KbHome.test.tsx` 不再写死版本。

## 2. 测试

新增 4 个单元测试：
- `a_snapshot_is_built_locally_and_copied_whole`：成功，`kb.db` 是新的，`kb.db.prev` 是旧的，没有残留
- `a_copy_that_fails_halfway_leaves_the_old_snapshots_and_no_litter`：拷到一半失败，旧快照不变
- `a_copy_that_does_not_match_is_never_placed`：拷贝被改了一个字节，SHA-256 不一致，不覆盖
- `a_failed_snapshot_removes_the_local_and_staged_temp_files`：硬盘侧无法写入，旧快照不变

原有 `db_snapshot_is_consistent_rotates_once_a_day_and_keeps_one_previous` 仍通过（目录里没有多余文件）。

真机集成测试 `exfat_disk_image_takes_a_snapshot`（`#[ignore]`，仅 macOS，`cargo test exfat_disk_image -- --ignored`）：`hdiutil create -fs ExFAT -attach` 建 64 MB 镜像，挂载后（`mount` 显示 `exfat, fskit`）用新流程做快照，通过；结束后 `hdiutil detach`。

7 项检查：tsc 通过；vitest 147 个文件 / 1577 通过；lint 通过；i18n:validate 通过；`cargo test -- --test-threads=1` 1497 通过、7 忽略（含新的 exFAT 测试）；clippy 通过；fmt 通过。

## 3. 需要知道的

- **没能在这台机器上复现"修之前失败"。** 同一个 exFAT（fskit）镜像上，旧做法（直接在盘上 `online_backup` 到 `kb.db`，测试里最后一步打印）返回 `Ok`。你们的失败发生在 USB 实盘上，镜像文件不一定走同样的共享内存路径。所以 exFAT 测试只能证明新流程在 exFAT 上通过，不能证明旧流程会失败。新流程不在硬盘上打开 SQLite，所以和失败原因（盘上 `-shm`）无关，但最终要靠 leader 在真实硬盘上点一次"立即备份"确认。
- 这台机器上 `/Volumes/Share` 当前是挂着的，我没有往里写任何东西。
- 硬盘上不再留 `kb.db.tmp-<pid>`；上次失败留下的旧 `kb.db.tmp-*` 若还在，不会被自动清理（本期没做）。
