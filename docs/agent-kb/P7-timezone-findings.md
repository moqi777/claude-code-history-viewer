# P7 补测发现：每日整理的带时区时间戳比较

状态：**已复现，未修改产品代码**。这涉及 Mac/Windows 共用逻辑，单独提交 leader 评估，不混入原验收第 3 节限定的 Windows 输出修复。

## 复现与影响

2026-10-18 在 Windows 安装版 `D:\AgentKB\AgentKB.exe` 上，用临时假会话、fake AI、每日整理时间 `00:00`、`min_messages=1` 运行 `--kb-sync --scheduled`。

- 假消息时间：`2026-10-17T23:22:03.702228+08:00`，实际为 UTC `2026-10-17T15:22:03.702228Z`。
- 当日整理截点：本地 2026-10-18 00:00，即 UTC `2026-10-17T16:00:00Z`。
- 消息早于截点，预期进入当日整理；实际当天轮次标为 done，`done=0`、`calls=0`，没有笔记。
- 将验收用例写为 CLI 常见的 UTC `Z` 时间戳后，同一安装版正常生成 1 条笔记。没有修改系统时间或真实记录。

根因定位到 `src-tauri/src/kb/digest/plan.rs` 的候选计数：

```sql
AND kind IN ('user','assistant') AND (ts IS NULL OR ts<=?3)
```

这里按字符串比较原始时间戳与 UTC 截点。不同偏移量的 RFC3339 文本顺序不等于时间顺序。对本轮临时数据库执行：

```sql
SELECT count(*) FROM messages WHERE ts <= '2026-10-17T16:00:00Z';
-- 0
SELECT count(*) FROM messages
WHERE julianday(ts) <= julianday('2026-10-17T16:00:00Z');
-- 1
```

`digest/input.rs` 的消息截取已经通过 `DateTime` 解析后比较；候选筛选先排除了会话，所以后续正确的截取逻辑无法补救。

这证明带偏移量记录可能被错误排除出本轮，并不证明本机真实 Claude/Codex 记录存在该格式或已经受到影响。本次没有检查真实会话内容。

## 建议后续修复范围

在公共逻辑中统一以真实时间比较候选消息，明确无时间戳/非法时间戳的处理，保持与 `input.rs` 一致。需要覆盖：UTC `Z`、正负偏移、相同瞬间不同表示、截点前后和小数秒；兼顾既有数据库中的原始文本，不能仅修复新增索引。候选计数查询需确认性能，再跑 Mac/Windows 回归。

一次性跨日验收使用 UTC `Z` 假数据，测试真实时钟跨日和任务触发；它不代表此边界问题已修复。
