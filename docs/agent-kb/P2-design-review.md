## 2. 必须修改的地方

### 2.1 备份遇到"文件被重写"后会永远卡住（必须修）

6.2 第 2 步规定：备份盘上的文件比源更长，或者开头 4KB 不一致，就"不动它，记一条 backup conflict"。

但 P1 的镜像规则里，源文件被重写时，会把旧镜像改名为 `.prev-<时间戳>`，再在**原文件名**下完整复制一份新的。这样一来，主目录里这个文件变短了，或者开头变了，备份盘上同名的旧文件就会一直被判定为冲突。结果是：**这个会话之后的新内容永远备份不上去**，而且每次同步都报一次错。

**要求：**
- 冲突时，把备份盘上的旧文件改名为 `<原文件名>.conflict-<时间戳>`（**不能以 `.jsonl` 结尾**），然后按新文件完整复制一份。这样仍然满足"备份里什么都不删"，新内容也能正常备份
- 写一条日志，但**不算错误**。只有改名或复制本身失败时，才记进 `errors`
- 补一个测试：主目录发生一次重写（产生 `.prev-*`）后，下一次备份之后，备份盘上同时有旧版本（`.conflict-*` 或 `.prev-*`）和完整的新版本，而且再跑一次不会报任何冲突

### 2.2 版本号要能区分

`package.json` 里的版本号是原项目的 1.32.0。改了的话，以后合并上游更新会冲突；不改的话，关于页显示 1.32.0，用户分不清是哪一版。

**要求：** `package.json` 的版本号保持和上游一致，不改。另外在 `kb` 模块里加一个常量 `AGENTKB_VERSION`，本期设为 `0.2.0`（第 N 期就是 `0.N.0`）。关于页和知识库主页显示为"AgentKB 0.2.0（基于 Claude Code History Viewer 1.32.0）"。

### 2.3 首次备份时间长，要让用户看得到

首次备份大约 2.9GB，拷到 U 盘可能要十几分钟。按设计它在收集锁里执行，这段时间里"立即收集"会显示"收集中"，用户会以为卡住了。

**要求：** 锁不用拆。但主页的状态要区分"正在收集"和"正在备份到移动硬盘（已完成 X%）"，按钮的提示也要相应改。备份中途退出 App 或拔盘后能续传，这一条你的设计已经覆盖，测试里要体现。
