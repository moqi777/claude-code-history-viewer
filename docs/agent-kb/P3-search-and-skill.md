# 第 3 期：全文搜索 + `--kb-search` + skill 一键安装

> 先读 `PLAN.md`、`P2-acceptance.md`。PLAN 第 3 节的架构决定、第 6 节的通用约束都适用。
> 遇到 **【检查点】** 必须停下，把产出交给用户转给 leader 审核，通过后才能继续。

## 1. 本期目标

做完后，用户能：

1. 在 Claude Code 或 Codex 里用大白话问以前的事，例如"之前那个 MQ 消息丢失的问题是怎么解决的"，Agent 自己调用 AgentKB 找到对应的会话，说出当时的结论，并给出能直接复制的 resume 命令
2. 在 AgentKB 首页搜索框里搜关键词（中文、英文、类名、报错信息都行），点结果直接跳到原会话里命中的那条消息
3. 在 App 里一键把 skill 装进 Claude Code 和 Codex，也能一键卸载

## 2. 范围

**本期要做：** 消息级全文索引（中文分词）、`--kb-search`、`--kb-show`、首页搜索、skill 安装和卸载、P2 留下的小问题（首页说明文字换行）。

**本期不做：** 语义搜索和向量（第 6 期）、AI 整理成笔记（第 4 期）、导出迁移、Windows。

## 3. leader 已定的事

| 项 | 决定 |
|---|---|
| 索引存放 | 放在 `kb.db` 里，用 SQLite FTS5。索引只是派生数据，`--kb-reindex` 能从 `raw/` 完整重建 |
| 中文分词 | 用 jieba（`jieba-rs`）在 Rust 里先切词，再存进 FTS5，查询时用同样的方法切词。不用 trigram，因为它匹配不了 2 个字的词（例如"死锁""限流"） |
| 索引哪些内容 | 用户消息和助手回复的正文必须索引。工具调用的命令和参数、报错类结果也要索引（"之前那个 NoSuchMethodError"这种问题靠它们才能搜到），但每条要截断（上限你在设计里定，并给出依据）。思考过程、大段文件内容、图片不索引 |
| 无界面命令 | `--kb-search "<问题或关键词>"`：返回命中的会话（标题、来源、客户端、项目、时间、命中片段、resume 命令、原会话位置）。`--kb-show <会话> [--around <消息>]`：返回命中消息前后的上下文，让 Agent 能读到当时的结论。两者都输出 JSON，也要有给人看的文本格式 |
| resume 命令 | Claude：`cd <cwd> && claude --resume <session id>`；Codex：`codex resume <session id>`（以本机 codex 0.162 的实际用法为准，要实测）。源文件已删除的会话不能 resume，给出 `--kb-show` 的用法 |
| 只读 | `--kb-search`、`--kb-show` 只读 `kb.db`，不加锁、不写入，也不顺带收集。结果里注明"数据截至 X"（上次收集的时间） |
| skill 安装位置 | Claude：`~/.claude/skills/agentkb/SKILL.md`；Codex：`~/.codex/skills/agentkb/SKILL.md`（两边本机都已有 skills 目录） |
| 对源目录只读规则的例外 | PLAN 第 3 节第 6 条已加例外：**只有**用户在 App 里点"安装 skill"时，才允许写这两个 `agentkb/` 目录，卸载时只删这两个目录。其他任何情况仍然绝不写 `~/.claude`、`~/.codex` |

## 4. 执行步骤

### 步骤 0：P2 遗留

首页说明文字在窗口较窄时句号会单独掉到第二行，修掉。

### 步骤 1：写设计说明 `docs/agent-kb/P3-design.md` 【检查点】

要回答下面这些问题，每一条都写出依据的文件和函数：

1. **表结构**：消息表、FTS5 表的字段，和 `sessions`、`files` 的关系；`INDEXER_VERSION` 怎么升级；首次建索引和增量更新怎么做（只处理新追加的部分，`.prev-*` 和重写怎么处理）
2. **分词**：jieba 的词典怎么带进程序、对二进制体积的影响；英文、数字、类名（`WechatAgreementRepository`）、包名、报错（`java.lang.NoSuchMethodError`）、路径怎么切；查询时怎么组合多个词（全部匹配还是部分匹配），怎么排序（BM25 再结合时间？）
3. **用本机真实数据量出来的数字**：索引占多少空间、首次建索引要多久、每次增量多久、一次查询多久。先在临时 HOME 里对一份真实数据的副本测，不要直接动 `~/AgentKB`
4. **`--kb-search` / `--kb-show` 的参数和输出格式**：给出完整 JSON 示例。参数至少有：来源、项目、时间范围、条数。一个会话命中多条消息时怎么合并
5. **自己搜到自己**：Agent 调 `--kb-search` 后，这次搜索的输出会写进当前会话，下次收集后又会被搜出来，越搜越乱。你打算怎么处理（例如 skill 里约定一个标记，索引时跳过带标记的工具结果），给出方案
6. **在 Agent 里能不能跑起来**：
   - Claude Code：调用二进制时会不会弹权限确认？SKILL.md 里怎么写能让它少问一次又不放开别的权限？
   - Codex：默认沙箱下能不能读 `~/AgentKB/kb.db`？SQLite 打开 WAL 库时要写 `-shm`，沙箱会不会拦？拦的话怎么办（例如 `immutable=1` 只读打开，代价是看不到还没写回主库的最新数据，要说明影响）
   - **这一条必须在本机实测**，用两个 Agent 真跑一次，把结果写进设计
7. **SKILL.md 的内容**：给出全文草稿。要写清楚：什么时候用（用户问"之前""上次""那个问题"等）、怎么调用、怎么读结果、搜不到时换关键词再搜（最多几次）、回答时要附上会话标题、时间和 resume 命令。要短，避免占用 Agent 太多上下文
8. **skill 的安装和卸载**：怎么判断已安装、版本怎么升级（App 升级后 skill 要跟着更新）、App 被移走后 skill 里的路径怎么办（参考 P2 定时任务的自动修复）、原子写入
9. **首页搜索**：界面草图；点结果后怎么跳到原会话里的那条消息（复用 P2 的 `kb://` 打开方式）
10. **改动清单和新依赖**

写完提交并推送，然后**停下**，等待审核。

### 步骤 2：索引和命令

按设计实现。`--kb-reindex` 要能从 `raw/` 重建全部索引。

### 步骤 3：首页搜索

搜索框、筛选、结果列表（标题、来源、项目、时间、高亮片段），点击后跳到原会话里的那条消息。

### 步骤 4：skill

- 设置页新增"让 Agent 能查历史"区块：分别显示 Claude、Codex 的安装状态，有"安装""卸载""测试"按钮
- "测试"按钮实际运行一次 `--kb-search`，显示"找到 N 个会话，用时 X 毫秒"
- 向导最后加一页"让 Agent 能查历史"，可以跳过；已经设置过的用户升级后，首页提示一次

### 步骤 5：测试

- Rust 单元测试：分词（中文、英文、类名、报错、路径）、增量索引、重写后索引正确、重建索引、自己搜到自己的过滤、skill 安装卸载（只碰 `agentkb/` 目录）
- **检索效果测试集**：从本机真实会话里挑 15 个"以后真会问"的问题（中文为主，含 2 个字的词、类名、报错），每个写明应该命中哪个会话。测出前 5 条的命中率，写进报告。挑问题时不要照着会话里的原话抄，要像用户回想时那样问
- 前端测试：搜索框、结果点击、skill 安装状态

## 5. 验收标准

**执行 AI 自己验证（报告里贴命令和输出）：**

1. 检索测试集前 5 条命中率 ≥ 80%，没命中的逐条分析原因
2. 一次查询 ≤ 300ms（本机真实数据量）；每次收集时增量索引额外耗时 ≤ 2 秒（没有大量新会话时）
3. `--kb-reindex` 后搜索结果和增量建出来的一致
4. 在 Claude Code 和 Codex 里**各真跑 3 个问题**（新开会话，只用大白话，不提 AgentKB），Agent 都自己调用了 skill，给出会话标题、时间和可用的 resume 命令；贴上对话记录。测试会话要在临时 HOME 或者能明显区分的项目目录里做，不要混进真实数据（P1 遗留第 5 项）
5. 用 resume 命令真的能回到那个会话（Claude、Codex 各试一次）
6. 安装和卸载 skill 前后，`~/.claude`、`~/.codex` 下除了 `skills/agentkb/` 以外没有任何变化（拍快照对比）
7. 自己搜到自己：连续搜 3 次同一个问题，再收集一次，第 4 次搜的结果里不出现前几次搜索产生的内容
8. PLAN 第 6 节的全部检查通过；写好 `docs/agent-kb/P3-report.md`，推送到 `origin/agent-kb`

**用户真机确认（报告最后单独列出清单）：**

9. 在 App 设置里安装 skill，然后在 Claude Code 里问一个自己记得的老问题，能找到
10. 在 Codex 里问一个，也能找到
11. 首页搜一个中文两字词（例如"死锁"），点结果能跳到那条消息

## 6. 注意

- 用户的 `~/AgentKB` 里有真实数据。建索引、测性能先在临时 HOME 里对副本做；在真实数据上第一次建索引之前，先备份 `kb.db`
- 测试时不能往用户真实的 `~/.claude/skills`、`~/.codex/skills` 里装东西。真机安装由用户自己点
- 遇到本文件没有覆盖、而且会影响设计的情况，先停下来提问
