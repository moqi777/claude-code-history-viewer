# 第 6 期：语义搜索（本地向量）

> 先读 `PLAN.md`、`P3-eval.md`、`P4.1-acceptance.md`、`P5-acceptance.md`。PLAN 第 3 节的架构决定、第 6 节的通用约束都适用。
> 遇到 **【检查点】** 必须停下，把产出交给用户转给 leader 审核，通过后才能继续。
> 版本 `AGENTKB_VERSION = 0.6.0`。

## 1. 本期目标

做完后：

1. 用户和 Agent **不用记准原话**也能搜到。例如搜"续航变短"能找到会话里写的是"掉电快""耗电"的那次；搜"怎么让终端开在指定文件夹"能找到写的是"Ghostty 默认目录"的那次
2. 原来靠关键词能搜到的，现在**一个都不能变差**
3. 全程在本机算，不把会话内容发到任何地方；用户平时感觉不到它在后台建索引

PLAN 第 4 节的验收标准：不用记准关键词也能搜到。

## 2. 范围

**要做：** 本地向量模型、增量建向量索引、关键词和向量的混合排序、`--kb-search` 接入、App 搜索接入、设置页（开关、模型状态、重建、测试）、新测试集、skill 模板更新、第 0 步小修。

**不做：** 调用任何在线向量服务或 AI 接口；用 AI 改写查询；Windows（第 7 期，但模型和运行库的选择要能在 Windows 上用）。

## 3. leader 已定的事

| 项 | 决定 |
|---|---|
| 在哪算 | **只在本机算。** 向量模型和推理运行库都放在本机，搜索和建索引时不联网 |
| 模型从哪来 | 模型文件太大，不放进安装包。设置页提供"下载模型"按钮，**只有用户点了才下载**，界面写清地址和大小；下载后按写死在程序里的 SHA-256 校验，不符就删掉并报错。另外支持"从本地文件夹选择模型"，给不方便联网的情况用。这是 PLAN 第 6 节"不联网"的**唯一例外**，只限这一次下载，下载以后完全离线 |
| 选哪个模型 | 候选：`bge-m3`（中英都好，约 570 MB 的 int8 版本）和一个小模型（例如 `bge-small-zh-v1.5` 或 `multilingual-e5-small`，约 100 MB）。**设计阶段两个都在真实数据上量**（第 4 节步骤 1），用数字选，由 leader 定 |
| 默认开不开 | 默认**关**。用户在设置页下载模型、点"测试"通过后自己打开，和每日整理一样 |
| 存在哪 | 模型放 `~/AgentKB/models/`。向量是派生数据，可以随时从 `raw/` 和 `notes/` 重建。P5 导出**不带**模型，向量带不带由设计量完大小和重建时间后提建议 |
| 给什么建向量 | 笔记（价值最高）、会话标题，以及 user/assistant 的正文按段切开。工具输出、大段代码、日志这类内容由设计决定要不要建、怎么截断，要给出理由。建之前先过 `kb/redact.rs` 脱敏，和全文索引一样 |
| 什么时候建 | 跟着定时收集增量建，只处理新增和变化的部分。**每次最多占用 N 秒**（设计里给出 N，建议 60 秒以内），用低优先级运行，峰值内存要有上限（设计里实测，建议 1.5 GB 以内；用户的电脑上常有别的工作在跑）。第一次全量建可以分多次收集慢慢完成，界面显示进度 |
| 怎么排序 | 关键词结果和向量结果**合并排序**（例如 RRF），笔记命中的会话仍然排在前面（P4.1 的规则不变）。只用向量、不看关键词的模式不做默认 |
| 输出 | `--kb-search` 的现有键名一个都不能改（`agentkb_marker`、`results`、`notes`、`has_note`、`hits`、`rank`、`resume` 等）。可以新增键，例如每条结果标出是"关键词命中""语义命中"还是"两者都有"，`mode_used` 可以加新的值 |
| 速度 | 没打开语义搜索时，一次 `--kb-search` 仍然 ≤ 300 ms。打开以后，**包括加载模型**，一次 ≤ 1.5 秒（`--kb-search` 每次都是新进程，模型加载时间要算进去）。达不到就在设计里说明，并给出办法 |
| 模型没准备好 | 模型没下载、文件坏了、向量还没建完，搜索**自动退回只用关键词**，照常返回结果，输出里说明原因，不报错 |
| skill | 模板升一版（`TEMPLATE_VERSION` 改为 4）。加上两句：一是"`has_note` 为 true、`hits` 为空，表示是靠笔记找到的"（P4.1 留下的）；二是语义命中的结果怎么理解。用户点一次"更新"即可 |

## 4. 执行步骤

### 步骤 0：小修

### 步骤 1：先写测试集，再写设计 【检查点】

**1a. 测试集 `docs/agent-kb/P6-eval.md`**，在跑任何语义检索之前写好并提交，做法和 `P3-eval.md` 一样：

- 新写 **15 道"换了说法"的题**：从本机真实会话里挑，问法故意不用会话里的原词（同义词、口语化、描述现象而不说名字），例如"续航变短"对"掉电快"。每题写上期望的会话，并说明会话里实际用的词
- 不用 `scratch/` 里的测试会话，也不用 AgentKB 自己的开发会话作为期望答案
- 原来的 16 道题（`P3-eval.md` 的 15 道加"电池 耗电"）作为"不能变差"的对照

**1b. 设计说明 `docs/agent-kb/P6-design.md`**，每一条都写出依据的文件和函数：

1. **模型和运行库**：两个候选模型各用什么推理库（例如 `ort` 调 ONNX Runtime，或者纯 Rust 的 `candle`）、安装包会大多少、Windows 上能不能用、许可证
2. **实测**（在临时 HOME 里，对真实库的副本）：两个模型分别量出
   - 全量建索引的耗时、峰值内存、向量占多大
   - 一次搜索的耗时：冷启动（含加载模型）和热的
   - 新测试集 15 题、原来 16 题的前 5 命中数：只用关键词、只用向量、混合，三种都要列
3. **切段**：怎么切、每段多长、哪些内容不建、为什么
4. **增量和后台**：怎么只算新增的；每次限时、低优先级、内存上限怎么做；和收集锁、整理锁的关系；第一次全量建怎么分批、怎么报进度
5. **存储**：表结构或者文件格式；schema 要不要升；`--kb-reindex` 和 P5 导出、导入怎么处理向量
6. **混合排序**：合并的公式和参数；笔记优先怎么保留；标题加分怎么保留；会话去重
7. **下载和校验**：地址、大小、SHA-256、断点续传或失败重来、代理；本地文件夹导入
8. **界面草图**：设置页（下载、进度、开关、测试、重建、占用空间）；搜索结果里的"语义命中"标记
9. **P4.1 和 P5 留下的问题**，在这期能不能顺带解决，解决不了就写原因：
   - AgentKB 自己的开发会话（有大量测试输出）常常排到前面
   - 同一批笔记，增量建出来的和整体重建的，分数不一样
10. **改动清单和新依赖**

写完提交并推送，然后**停下**，等待审核。

## 5. 验收标准

**执行 AI 自己验证（报告里贴命令和输出，全部在临时 HOME 里）：**

1. **换说法能搜到**：`P6-eval.md` 的 15 题，混合模式前 5 命中数**明显高于**只用关键词（报告里列出每题两种模式的名次）。具体要求在设计审核时定
2. **不变差**：原来 16 道题，混合模式的前 3 命中数不少于 16/16（P4.1 的结果），"电池 耗电"仍然是第 1
3. **退回**：删掉模型、改坏模型文件、向量只建了一半，三种情况下 `--kb-search` 都正常返回关键词结果，并说明原因
4. **增量**：新增一个会话、给已有会话追加消息，下一次收集后能用语义搜到；没变化的部分不重新计算（日志里有计数）
5. **不打扰**：真实库大小的副本上，每次收集占用的时间不超过设计定的上限，峰值内存不超过上限（贴出测量方法和数字）；第一次全量建完以前，搜索照常可用
6. **速度**：没打开语义搜索时 ≤ 300 ms；打开以后 ≤ 1.5 秒（含加载模型），列出 10 次的耗时
7. **离线**：建索引和搜索时断网（或者用沙盒禁止联网）照常工作；只有点"下载模型"时才会联网
8. **不碰源目录**：前后对 `~/.claude`、`~/.codex` 拍快照对比，没有变化
9. **导出导入**：按设计的方式，P5 的导出、导入仍然通过（会话数、笔记数、16 道题的结果一致）
10. PLAN 第 6 节的全部检查通过；写好 `docs/agent-kb/P6-report.md`，推送到 `origin/agent-kb`；**不要安装到 /Applications**，等 leader 验收

**用户真机确认（报告最后单独列出清单）：**

11. 在设置页下载模型、测试、打开语义搜索；等第一次建完（界面有进度），期间电脑用着不卡
12. 在 App 里搜一个"记得意思、记不得原话"的问题，能找到
13. 在 Claude Code 里用自然语言问一个换了说法的问题，Agent 通过 skill 找到对应的会话
