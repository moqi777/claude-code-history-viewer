# P7.5 报告：整理成功后旧失败还挂着

版本 `0.7.5`（`mod.rs`、`branding.ts`、`fixtures.ts`）。包：`src-tauri/target/release/bundle/macos/AgentKB.app`（ad-hoc 签名，`codesign --verify --deep --strict` 通过；主程序 `Contents/MacOS/AgentKB` SHA-256 `38cdfbd4f10f62c3cef1e0724b4b058752fb5cebd84cd7dceb821f7fa0b016be`，61,637,472 字节）。**没有安装。**

## 改了什么

1. **"可输入"类型只定义一处**：`store::INPUT_KINDS`（`user`、`assistant`、`tool_use`、`tool_error`）。`input::load_items`、`plan.rs` 的候选计数和会话最大 seq、失败判断都用它，只查 kind/seq，不读正文。
2. **当前失败改成读时计算**（`store::failures`）：一条失败仍算未解决，当且仅当
   - 失败范围内（`seq <= seq_to`）有可输入消息没被 `digested_seq` 覆盖，并且
   - `seq_to` 之后没有新的可输入消息（长出新内容的会话交给正常增量整理）。
   历史行不删不改；旧版留下的那 3 条（66/67、150/151、188/191）装上 0.7.5 后下次读状态就消失。只成功了前一块的，范围里仍有未整理的可输入消息，继续显示、可以重试。
3. **口径一致**：`is_held` 和候选筛选改用"最新可输入消息 seq"（新增 `store::newest_input_seq`）。只追加 `tool_result` 的会话既不会重新出现在失败里，也不会被当作有新内容去调 AI（候选的新消息计数本来就只数 user/assistant，这次再用同一份 kind 集合）。失败记录里写入的 `seq_to` 仍是全部消息最大 seq，没改，保持历史语义。
4. **重试没有新内容时返回结构化原因**：`RunStarted::Nothing { reason, message }`，`reason` 为 `up_to_date` / `not_indexed` / `no_kb`。前端 `digestNothing.ts` 按 `kb.digest.toast.nothing.<reason>` 显示，5 种语言都有（如"这个会话已经整理完了，没有新内容。"），不再显示后端英文。`KbDigestCard` 和 `KbSessionNotes` 共用。

## 测试

后端（临时 HOME + 模拟 AI，都在 `digest/tests.rs`，新增 5 个）：
- 失败末尾有 1 个、3 个 `tool_result`，以及 66/67、150/151、188/191 边界：成功后失败数归零，历史 failed 行仍在，`next_chunk` 为空，不启动模型。
- 只成功前一块：仍显示失败，仍有可读消息可重试；从未成功过的失败同样不会被当成已解决。
- 成功后只追加 `tool_result`：不在失败里，整轮运行 0 次 AI 调用；追加真实消息后失败消失，按正常增量规则可再整理。
- `is_held`：只追加 `tool_result` 仍 held，来了可读消息才放开。
- `session_blocker`：已整理返回 `up_to_date`，不在索引返回 `not_indexed`。

前端新增 1 个（重试已整理会话显示翻译后的原因），并更新了 1 个旧断言。

7 项检查：tsc、lint、i18n:validate 通过；vitest 1590 通过；`cargo test -- --test-threads=1` 1529 通过、8 忽略；clippy `-D warnings`、`cargo fmt --check` 通过。

## 已知取舍

- 失败对应的会话已不在索引里（没有任何消息行）时，现在不再显示为当前失败（旧逻辑会显示但无法重试）。历史行仍在。
- 失败判断不带截止时间：范围内有未覆盖的可读消息就算失败，截止时间只影响整理本身。
- 没有在真实数据上运行；Windows 真机上那 3 个会话的消失需要 Windows 侧装 0.7.5 后确认。
