# 第 9 期：团队共享（方案，待用户确认后拆任务）

> 状态：方案稿，2026-11-22。用户确认后，leader 再拆成 9a–9d 的任务文件交给执行 AI，每期照旧先出设计（检查点）。
> 合规：用户的 leader 已同意做这件事。

## 1. 目标

团队约 12 名开发，每人装 AgentKB，照旧自动收集、备份、整理自己的会话。在此基础上：

- 每人的**笔记**自动推到团队云主机（内网一台闲置 Windows）
- 在 Claude Code / Codex 里问"之前……怎么解决的"，skill 同时搜**本机**和**团队**，合在一起给结果
- 看到别人有用的笔记，可以**申请看那个会话的原文**，对方同意后可看

## 2. 已定的事

| 项 | 决定 |
|---|---|
| 共享什么 | 只自动推**笔记**（问题、原因、办法、结论、出处）。原始会话留在本机 |
| 看原文 | 以**整个会话**为单位申请（一个会话的几条笔记只需申请一次）；对方同意后，对方电脑把这个会话传到云主机，只有申请人能看，到期自动删除（保留天数在运营平台可配） |
| 按目录三档 | **不共享** / **共享笔记**（看原文要申请）/ **完全公开**（笔记和原文都直接可看）。按会话的工作目录判断，设在上级目录对下级生效 |
| 默认档 | **共享笔记**（怕大家装了不知道开）。不想公开的自己改成不共享 |
| 提醒 | 钉钉群自定义机器人（用用户自己的账号建），@ 对应的人；注册时填手机号。云主机能上外网 |
| 身份 | **每台设备一对密钥**（Ed25519），私钥只在本机，公钥在运营平台；人名下可挂多台设备。换电脑：旧电脑点"添加新设备"出一次性码，新电脑填入；旧电脑丢了由管理员在运营平台改绑并停用旧设备 |
| 加入团队 | 运营平台生成**邀请链接** → 云主机上的下载页 → 装好首次打开自动带上邀请码，填花名和手机号完成注册 |
| 更新 | 打开底座原有的自动更新，指向云主机（需要一把更新签名密钥） |
| 网络 | 只走内网 HTTP；外网那套先不做 |

## 3. 整体样子

```
每个人的电脑（AgentKB 客户端）                 云主机（闲置 Windows，内网）
  收集 → 备份 → 每日整理笔记                     团队服务（AgentKB 无界面模式）
  按目录档位筛选、脱敏  ── 推笔记 ──────────▶      团队笔记库 + 全文/语义索引
  skill 搜索：本机 + 团队 ◀── 搜团队 ──────        原文中转区（到期自动删）
  申请/同意原文 ◀──── 申请与授权 ────────▶        运营平台（成员、设备、邀请、配置）
                                                   下载页 + 自动更新
                                                   钉钉机器人 ──▶ 团队钉钉群
```

## 4. 主要流程

**加入**：管理员在运营平台生成邀请链接发群里 → 同事点开下载安装 → 首次打开填花名、手机号 → 本机生成密钥、公钥上传 → 设置向导显示"以下目录默认共享笔记"，可当场改 → 完成。

**每日推送**：每日整理完 → 按目录档位挑出要推的笔记 → 脱敏 → 推送（失败下次补）。笔记重新整理后按笔记 ID 覆盖。目录改成"不共享"后，下次同步撤回那个目录已推的笔记。

**首次推送缓冲**：装好后第一次推送推迟到次日，App 首页提示"明天将首次共享 N 条笔记"，并给出改设置的入口。默认开共享，又让人有机会反悔。

**搜索**：skill 调本机命令 → 本机搜 + 请求团队搜 → 合并排序，团队结果标"团队 · 花名 · 日期"。云主机连不上时只搜本机，结果里说明。

**申请原文**：A 在团队笔记上点"申请查看原文"（可附一句原因）→ 云主机记下申请，钉钉 @ B → B 的 App 显示申请，可预览要发出的内容（已脱敏）→ 同意 / 拒绝 → 同意后 B 的电脑上传这个会话 → 钉钉 @ A → A 在 App 里用会话查看器看 → 到期删除。B 一直不处理，申请过期作废。"完全公开"目录的会话，申请自动通过，B 的电脑在线时下一次同步就上传。

**换电脑 / 加设备**：见第 2 节"身份"。

**离组**：管理员在运营平台停用此人，可一键删除他在云上的全部笔记和原文。

## 5. 隐私和安全

- 原文默认不出本机；只有本人同意或"完全公开"目录才会上传，且只给申请人、到期删除
- 推送前脱敏（复用 `kb/redact.rs`），原文上传前同样脱敏
- 每个请求用设备私钥签名，云主机按公钥核对；设备可单独停用
- 云主机数据只在内网，按现有移动硬盘备份方式备份
- 用户本机能看到"我共享了哪些笔记"，可单条撤回

## 8. 留给设计阶段回答的问题

1. 团队服务用底座的 `--serve`（Axum）扩展，还是 AgentKB 自己另起一个无界面模式；Windows 上怎么开机常驻
2. 云主机上的团队笔记怎么建关键词和语义索引；客户端不下载模型也能用团队语义搜索
3. 一个会话原文很大（Codex 可到几百 MB）时，上传上限和压缩方式
4. 签名请求的格式、防重放；一次性码的有效期
5. 笔记里引用的出处（会话 ID、消息序号）在团队侧怎么显示，和原文申请怎么关联
6. 现有客户端（0.8.x）没有团队功能时，云主机和客户端的版本兼容
