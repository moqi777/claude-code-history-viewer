## 2. 实现时补上

1. **读 `kb.db` 不能用 `immutable`**：设计 §4 写的是"用不可变或只读方式打开"。`immutable=1` 读不到 WAL 里还没写回主文件的数据，我自己在 P4 时就因为这个误判过一次。一律用 `mode=ro`。加一个测试：收集刚写进 WAL 的新消息，下一轮建向量时要能读到。
2. **要在真正的后台优先级下实测**：13.5 段/秒是在正常优先级下量的。设成后台 QoS 后，macOS 只用能效核，速度可能慢好几倍。报告里给出"低优先级 + 3 线程"下的实测速度，以及第一次全量建按收集间隔要多久。另外，设置页加一个"现在全部建完"按钮：用正常优先级一直算到建完，有进度，可以取消，给想马上用的人。
3. **锁要协调好**：`embed.lock` 也要纳入换数据目录（`migrate_dir`）和 P5 导入。正在建向量时，这两个操作要等它结束，或者提示用户。P5 导出向量文件时，要用 SQLite 的备份接口拍一份一致的快照，不能直接复制文件。
4. **构建时联网**：可以用 `ort` 默认的方式在编译时下载 ONNX Runtime。报告里写明 ONNX Runtime 的版本和库文件的哈希。打包后验证三点：签名校验通过；断网时建索引、搜索都正常；安装包没有在运行时去下载任何东西（验收第 7 项）。
5. **保密题的跑法**：我会用和 `p6-evidence/` 一样的调用方式（`--kb-search` 整句、默认参数）。请在报告里写清楚，怎样对一个临时 HOME 打开语义搜索、建完索引，以及要设哪些环境变量或参数，方便我直接照着跑。
