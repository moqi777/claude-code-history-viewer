## 2. 修复

### 2.1 超量笔记

- prompt 原先没有总数上限；现明确每次最多 8 条，包含更新已有笔记；主题更多时选最有价值的 8 条。
- Claude schema 已有 `maxItems:8`。Codex schema 保留 P4 实测可用的无 maxItems/maxLength 版本（P4-design §5 已说明接口兼容性），由 prompt 和本地校验共同限制。
- `validate::check_with_log` 只保留前 8 条，顺序和内容不变；多出的数量记录一行 digest 日志；保留条目的范围、长度、关键词、引用 ID 与脱敏校验继续执行。
- 单元测试覆盖 9→8、内容/顺序不变、只记一次日志、前 8 条不合规仍失败；模拟 CLI 整轮测试检查写 notes 文件、入库 8 条及日志。
- 在收到 AI reply 后、内容校验前记录 token 数，避免格式校验失败时连已发生的用量也查不到。该日志不包含回答正文。

### 2.2 Codex 路由错误

**证据与边界：** 当前 AgentKB 配置使用 `OpenAI/Codex/bin/codex.exe`，本机 `--version` 为 `codex-cli 0.163.0`，默认模型、`codex_reasoning=low`。10 月 18 日 digest 日志共有 48 次 routing failed、5 次 routing timed out（含自动重试和后来成功的会话），不能把这些日志条数当作独立失败会话数。`019e3ffa` 于 16:23 超时、16:34 用同一整理流程成功；Claude 来源的 `4d91bed3` 也在 Codex 引擎下遇到相同错误，后续成功。因此不是 Claude CLI 报错，也没有证据证明由某个来源或文件大小触发。

调用路径检查：工作目录始终为 AgentKB 的 digest-work，创建成功后才启动；不是原会话 cwd。Codex 已设置 `--skip-git-repo-check`、`--ignore-user-config`、`--ignore-rules`，参数没有按会话大小改变。没有为了猜测原因而读取认证文件、清空账户环境、改变用户工作区或放宽工具权限。

**AgentKB 可修复的误判：** 旧 `parse_codex` 记住第一条 `error`，即使随后 `turn.completed` 且进程退出 0，也返回失败。`Reconnecting...` 是明确存在于历史 last_error 的通知。现只有在完成事件、退出成功且没有 `turn.failed` 时，才允许忽略临时错误；最终失败/非零退出仍返回失败。回归测试覆盖重连后成功、最终失败、非零退出和 stderr 路由错误。

[Codex 官方非交互文档](https://learn.chatgpt.com/docs/non-interactive-mode)说明 JSONL 输出区分 `error`、`turn.completed` 和 `turn.failed`。官方资料没有给出这条 workspace routing 错误的确切触发条件；历史日志也未保存完整 CLI 事件序列，**不能断言 17 个历史失败全是误判，或已经修复 Codex 服务本身**。

真正失败时提示：Codex 工作区路由连接失败或超时；检查网络/代理，在 Codex 确认当前工作区可用，再到每日整理设置测试后重试。保留原始错误短文，方便排查。没有凭空将它归类为未登录/额度耗尽。

### 2.3 时区与小数秒

- 候选统计读取索引中的 kind/ts，复用 input 的 RFC3339→UTC 解析，按真实瞬间比较，保留纳秒精度；不再将字符串 `ts<=cutoff` 当时间比较。
- 和 `input::load_items` 一样按 seq 扫描，在第一条超出截止时间的有效消息处停止，包含 tool_use/tool_error 边界；缺失或不可解析的时间戳沿用 input 行为。
- 父/子会话最后活动也改为先解析再求最大值，候选的 recent/quiet 筛选和执行前 quiet 检查共用同一函数。
- 截止时间序列化保留小数秒。测试覆盖 `+08:00`、负偏移、`Z`、纳秒边界、同一瞬间的不同写法、空/坏时间戳，以及子会话不同偏移对 quiet/recent 的影响。
- 直接适用于已有索引，无需重建真实数据库。
- 查询检查使用 D 盘临时模拟库（100 个会话、20 万条消息）：EXPLAIN 仍为 `SEARCH messages USING INDEX sqlite_autoindex_messages_1 (file_id=? AND seq>?)`；完整查询并取回 kind/ts 共 265.5 ms，不取正文。此值仅为 SQLite 查询和 Python fetch，不包含 Rust DateTime 解析，不作为端到端性能结论。
