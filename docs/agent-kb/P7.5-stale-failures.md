# P7.5：整理成功后旧失败还挂着（版本 0.7.5）

## 问题

Windows 真机：3 个会话 10-19 上午已重试成功（笔记、游标、轮次都一致），"整理失败"窗口仍显示旧失败；点"重试"弹英文提示 `nothing new in this session since its last note`，什么也不做。诊断见 `P7.4-windows-retry.md`（证据完整，leader 认可）。

根因：失败记录的 `seq_to` 用的是全部消息的最大 seq（含 `tool_result`），整理游标只到最后一条"可输入"消息（`user`、`assistant`、`tool_use`、`tool_error`）。会话末尾是 `tool_result` 时，游标永远追不上，`store::failures` 一直认为没解决。

## 要求

1. 当前失败的判断改成：旧失败范围内（`seq <= item.seq_to`）**可输入消息**的最大 seq，已被 `digested_seq` 覆盖，就算已解决，不再出现在失败列表里。读的时候算，旧数据（这 3 条）装上新版就消失；历史行不删、不改
2. "可输入"的类型集合只定义一处，`input::load_items` 和失败判断共用；只查 kind/seq，不读正文
3. 复核 `store::is_held` 和候选筛选里"有没有新内容"的比较，口径要一致：只追加了 `tool_result` 的会话，不应重新出现在失败里，也不应被当成有新内容去调 AI
4. 只成功了前一部分、失败范围里还有没整理的可输入消息时，仍显示为失败，能重试
5. "重试"遇到没有新内容时，返回结构化原因，前端用中文等 5 种语言显示，例如"这个会话已经整理完了，没有新内容"；不要显示后端英文原文
