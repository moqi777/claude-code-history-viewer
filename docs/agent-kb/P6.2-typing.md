# 第 6.2 期：搜索框打字被打断

> PLAN 第 6 节的通用约束都适用。版本 `AGENTKB_VERSION = 0.6.2`（Rust 和前端两处都要改）。不要安装到 /Applications。

## 1. 问题（用户真机，0.6.1，2026-10-17）

用户用中文输入法在 App 的搜索框里打字时，自动搜索会打断输入。截图里有两个现象：

- 结果里高亮了单个字母 `u`、`s u do` 这类片段，说明搜索拿到的是**拼音还没选字时的半截内容**
- 第二条结果的标题是半透明的，像是结果在被反复刷新

leader 看过的代码：`src/kb/KbSearch.tsx` 的 `SearchBox`，`onChange` 每次都写进 store，停 300 ms 就调用 `runSearch`，没有处理输入法的组字（composition）状态。打开语义搜索后，每次搜索在 App 进程里加载约 2 GB 的模型（P6 报告第 7 节），边打字边搜会反复加载，更卡。`KbNotes.tsx` 的笔记搜索也是同样的写法。

## 2. 要求（2026-10-17 按用户意见改）

用户的习惯是打完字按回车。**改成不自动搜索**：

1. **只在两种情况下搜索**：按回车；点输入框右边新加的**"搜索"按钮**。打字过程中一律不搜。会话搜索和笔记搜索都这样改
2. **输入法的回车不算**：用拼音输入法时，组字过程中按回车是在确认输入（例如把 `usb` 直接上屏），**不能触发搜索**。判断 `isComposing`（以及 WebKit 上 `keyCode === 229`）。只有不在组字时按的回车才搜索
3. **搜索中的状态**：按钮显示"搜索中"（转圈）。搜索中再次按回车或点按钮，以最新的一次为准，过期的结果不覆盖新的（已有 `searchEpoch`，确认它是对的）。搜索期间输入框照常可以打字，不被重新挂载
4. **清空**：点 ✕ 或按 Esc 清空输入框，同时清空结果，回到默认列表（和现在一样）
5. **标题半透明**：查清原因。如果是结果被反复刷新造成的，改成只在按回车时搜之后应该就没了，确认一下；如果是别的原因，单独修
6. **语义搜索的耗时**：不再边打边搜后，每次搜索仍要在 App 进程里加载约 2 GB 的模型。量出 App 里一次搜索的实际耗时（加载模型、计算各多少），写进报告。超过 1.5 秒的话，提出办法，由 leader 决定
7. 新增的按钮文字走 i18n（5 种语言）；原来的搜索结果、键名、排序都不变

## 3. 测试

- 前端测试：打字过程中不调用搜索；按回车调用一次；组字中按回车（`isComposing` 为真或 `keyCode` 229）不调用；点按钮调用一次；连续两次搜索只有后一次的结果生效；Esc 和 ✕ 清空
- 7 项检查全过

## 4. 交付

写 `docs/agent-kb/P6.2-report.md`（原因、方案、数字），推送到 `origin/agent-kb` 后停下等验收。用户真机确认：用拼音输入法连续打一句话，不被打断；按回车或点"搜索"出结果；拼音里夹英文时，确认英文的那一下回车不会触发搜索。
