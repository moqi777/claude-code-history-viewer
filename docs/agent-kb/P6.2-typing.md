# 第 6.2 期：搜索框打字被打断

> PLAN 第 6 节的通用约束都适用。版本 `AGENTKB_VERSION = 0.6.2`（Rust 和前端两处都要改）。不要安装到 /Applications。

## 1. 问题（用户真机，0.6.1，2026-10-17）

用户用中文输入法在 App 的搜索框里打字时，自动搜索会打断输入。截图里有两个现象：

- 结果里高亮了单个字母 `u`、`s u do` 这类片段，说明搜索拿到的是**拼音还没选字时的半截内容**
- 第二条结果的标题是半透明的，像是结果在被反复刷新

leader 看过的代码：`src/kb/KbSearch.tsx` 的 `SearchBox`，`onChange` 每次都写进 store，停 300 ms 就调用 `runSearch`，没有处理输入法的组字（composition）状态。打开语义搜索后，每次搜索在 App 进程里加载约 2 GB 的模型（P6 报告第 7 节），边打字边搜会反复加载，更卡。`KbNotes.tsx` 的笔记搜索也是同样的写法。

## 2. 要求

1. **组字期间不搜索**：输入法在组字时（`compositionstart` 到 `compositionend`），不触发搜索，也不因为搜索状态变化而让输入框重新挂载或丢失组字。组字结束后再按停顿规则搜。会话搜索和笔记搜索都要改
2. **打字过程中不卡**：先找出语义搜索在 App 里的实际开销（加载模型、计算各多久，界面线程有没有被占）。然后定方案，例如：模型在一段时间内留在内存里不重复加载；或者打字时只用关键词，停下来、按回车后再补语义结果；或者改成子进程搜索。方案和数字写进报告，由 leader 验收时看
3. **过期的结果不覆盖新的**：已经有 `searchEpoch`，确认它在组字、快速连续输入时都对
4. **标题半透明**：查清原因。如果是刷新动画被反复触发，就随第 1、2 条一起解决；如果是别的原因，单独修
5. 原来的搜索结果、键名、排序都不变

## 3. 测试

- 前端测试：模拟组字事件（`compositionstart`、带拼音的 `input`、`compositionend`），断言组字期间没有调用搜索、结束后调用一次；连续输入时只有最后一次结果生效
- 在打好的包里量：语义开时，打字过程中的搜索调用次数和每次耗时（日志或计数）
- 7 项检查全过

## 4. 交付

写 `docs/agent-kb/P6.2-report.md`（原因、方案、数字），推送到 `origin/agent-kb` 后停下等验收。用户真机确认：用拼音输入法连续打一句话，不被打断，结果正常。
