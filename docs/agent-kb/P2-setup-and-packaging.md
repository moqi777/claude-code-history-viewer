# 第 2 期：设置向导 + 配置 + 知识库主页 + 移动硬盘备份 + 正式打包

> 先读 `PLAN.md` 和 `P1-acceptance.md`。PLAN 第 3 节的架构决定、第 6 节的通用约束都适用。
> 遇到 **【检查点】** 必须停下，把产出交给用户转给 leader 审核，通过后才能继续。

## 1. 本期目标

做完后，用户能：

1. 安装一个叫 **AgentKB** 的正式 App（放在 `/Applications`），不会和原版 App 冲突，也不会被原版的自动更新覆盖
2. 第一次打开时跟着向导一步步完成设置，每一步都能当场测试
3. 在设置页随时修改：数据目录、收集频率、收集来源、排除路径、移动硬盘备份
4. 在知识库**主页**（独立页面，不是弹窗）看到全部状态、手动收集和备份、浏览备份的会话
5. 插上移动硬盘，备份自动多存一份；拔掉也不报错

## 2. 范围

**本期要做：** P1 遗留问题、App 改名和改标识、关闭自动更新、处理反馈入口、打包、定时任务改用正式 App 路径并能自动修复、配置读写、设置向导、知识库主页、设置页、移动硬盘备份、更换数据目录。

**本期不做：** 全文搜索、skill、AI 整理（向导里也不要放整理相关的步骤，第 4 期再加）、导出迁移、Windows。

### 步骤 2：改名、打包、定时任务路径

- `productName` 改为 `AgentKB`，`identifier` 改为 `io.github.moqi777.agentkb`。界面上原来显示 "Claude Code History Viewer" 的地方，改成 AgentKB（关于页可以保留"基于 Claude Code History Viewer 二次开发"的说明和原作者的 MIT 版权声明）
- 关闭自动更新，修改反馈入口（见第 3 节）
- 打包：`pnpm exec tauri build`，Apple Silicon 单架构即可。App 没有签名，在报告里写清楚第一次打开时的操作（右键 → 打开，或者在系统设置里允许）
- **定时任务的路径自动修复**：App 每次启动时检查已安装的 plist：如果 `ProgramArguments` 里的可执行文件路径和当前 App 的路径不一样（App 被移动、重装，或者 plist 还是开发期的 debug 路径），自动重新安装，写一条日志，并在主页提示"定时任务已更新到新位置"
- 主页要能看出定时任务失效：plist 指向的可执行文件不存在时，显示"定时任务已失效"，并提供"修复"按钮

### 步骤 3：配置和设置页

- 可配置项：数据目录、收集间隔（5、10、15 分钟或自定义，最少 1 分钟）、收集来源开关（Claude、Codex）、排除路径前缀列表、移动硬盘备份（开关、目标位置）
- 每个配置项都有**测试按钮**，并给出明确结果，例如：
  - 数据目录 → "可写入，剩余空间 120GB，现有数据 3.1GB"
  - 来源 → "找到 Claude 40 个会话（320MB）"
  - 移动硬盘 → "已连接，可写入" 或 "未连接"
- 改收集间隔后，定时任务自动按新间隔重新安装
- 写配置要用"临时文件 + rename"的原子写法；配置文件坏了的话提示用户，并允许恢复默认值，不能直接崩溃

### 步骤 4：设置向导

- 没有 config.json 时，打开 App 自动进入向导；设置页里可以随时重新打开
- 步骤：
  1. 欢迎页，并检测本机的 Agent：列出找到的 Claude 和 Codex 目录、会话数、占用空间
  2. 选择数据目录：默认 `~/AgentKB`。显示需要的空间和剩余空间。如果目录里已经有数据，提示"检测到已有数据，将继续使用"
  3. 选择收集间隔
  4. 移动硬盘备份：可以跳过
  5. 确认：显示汇总 → 点"开始"→ 执行首次收集（有进度）→ 安装定时任务 → 显示结果
- 每一步都能返回上一步。中途关掉 App，下次从头开始即可，但不能留下一半配置

### 步骤 5：移动硬盘备份

- 目标位置是移动硬盘上的一个文件夹，例如 `/Volumes/<盘名>/AgentKB-backup/`
- **用卷的 UUID 识别是哪块盘，不能只看盘名。** 更关键的是：硬盘没插时，`/Volumes/<盘名>` 可能只是系统盘上的一个普通文件夹，写进去就等于写到了系统盘。所以每次备份前都要确认目标确实在设置时选定的那块盘上（UUID 一致），否则跳过
- 每次 `--kb-sync` 主流程完成后，如果盘已经连接，就做一次增量备份：
  - `raw/` 下的文件只追加、不删除，复制方式和 P1 的镜像一样（按长度增量追加；`.prev-*` 文件整份复制）
  - `kb.db` 用 SQLite 的 online backup API 生成一致的快照，每天最多一次
  - 主数据目录里删掉的东西，备份里**不删**
- 盘没连接：静默跳过，记日志，不算错误
- 主页显示"上次备份到移动硬盘：X"。超过 7 天没备份时显示提醒
- 主页有"立即备份"按钮，和收集共用并发锁

### 步骤 6：知识库主页

- 做成独立的视图（不再用弹窗），从顶部工具栏或侧栏都能进入
- 状态区：上次收集、定时任务状态、按来源统计的会话数、源文件已删除的会话数、移动硬盘备份状态、数据目录占用空间
- 操作：立即收集、立即备份、打开设置
- 会话列表：按来源、客户端、项目、时间筛选；默认隐藏空会话；可以只看"源文件已删除"的会话
- 点击会话：在查看器里打开，中间栏和顶部要显示正确的来源和项目
- 耗时较长的操作要有进度或"进行中"状态；出错时要给用户看得懂的提示，不能只写到 console

### 步骤 7：测试

- Rust 单元测试：配置读写和升级、配置文件损坏时的处理、移动硬盘的 UUID 校验（包括"盘没插、但路径存在"的情况）、备份的增量追加和不删除规则、plist 路径不一致时的自动修复、更换数据目录的迁移和中途失败
- 前端测试：向导各步骤的前进、后退和跳过；设置页的测试按钮
- 真实数据：在用户本机用打包好的 App 走一遍

## 5. 验收标准

**执行 AI 自己验证（报告里贴命令和输出）：**

1. 打包出的 `AgentKB.app` 装进 `/Applications` 后能正常打开。plist 的 `ProgramArguments` 指向 `/Applications/AgentKB.app/...`
2. 把 App 换个位置再打开：定时任务自动更新到新路径；主页给出提示
3. 运行时不会访问原项目：抓一次 App 启动和使用过程中的网络请求，或者在代码里证明 updater 已移除、前端没有请求 GitHub API；反馈入口指向 `moqi777` 的仓库
4. 移动硬盘（或用 `hdiutil` 创建并挂载的磁盘镜像来模拟）：挂载后一个收集周期内备份完成，和 `raw/` 逐字节一致；卸载后同步正常完成，并且**系统盘上没有多出 `/Volumes/<盘名>` 文件夹**
5. 更换数据目录：数据完整迁移到新位置（逐字节校验），旧目录保留不删，之后的收集写到新目录
6. P1 遗留问题逐条修复，有测试或复核记录
7. PLAN 第 6 节列出的全部检查通过
8. 写好 `docs/agent-kb/P2-report.md`，所有改动推送到 `origin/agent-kb`

**用户真机确认（执行 AI 在报告里给出检查清单）：**

9. 把 config.json 临时改名，模拟新用户：5 分钟内走完向导，每个测试按钮都给出明确结果
10. 注销后重新登录：`sync_runs` 里能看到一条 `trigger=schedule` 的补跑记录
11. 知识库主页：从会话列表打开一个 Codex 会话，顶部和中间栏显示的是 Codex 及其项目
