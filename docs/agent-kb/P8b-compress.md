## 2. 已经定的事（不用再讨论）

沿用 `P8-design.md` 和审核意见：

| 项 | 决定 |
|---|---|
| 存法 | 整条 zstd 流，级别 9，文件名 `X.jsonl.packed.zst`；`byte_off`、`mirror_offset` 含义不变（按未压缩算） |
| 标记 | `files.packed`，schema 升到 v6（P7 没加迁移，不会撞） |
| 什么算旧 | `last_activity_at` 和 `src_mtime_ns` 都早于 N 天；没有消息时间的用文件时间 |
| 不压 | 小于 4 KB、大于 1 GB、`is_compressed=1`、已 `packed=1` |
| 默认 | 开，N = 30 天，可关、可改天数 |
| 写入顺序 | 临时文件 → 解压校验 SHA-256 一致 → rename → 数据库事务 → 最后删原文件；任何一步被杀，数据库指向的文件都完整 |
| 旧会话又有新消息 | 先解包回普通文件再追加（`P8-design.md` 第 3 节的 5 步） |
| 什么时候跑 | 定时收集里顺带做，每次限时 20 秒、低优先级；设置页有"现在压缩一遍" |
| 旧版本 | 0.7.x 打不开 v6 库，干净拒绝，接受 |
| 导入合并 | 同一会话两种存法第一版留两份 |
| 移动硬盘 | 备份照搬 `raw/` 现状（压的就是压的）；硬盘上的旧未压缩文件，证明内容相同再删，同 P8a |

## 3. 0.6.3 之后新增、设计里没有的地方

1. **从硬盘恢复**（`restore.rs`，P7.3）：恢复出来的库里有 `packed=1` 的行，要能读、能继续收集
2. **每台电脑一个备份子文件夹**（`backup.rs`、`backup_dir.rs`，P7.4/7.6）：压缩后的文件按原路径进各自子文件夹
3. **重复备份清理**（`dedupe.rs`，P8a）：Codex 之后又把我们压过的会话压成 `.zst` 时，留下的 `.packed.zst` 由它按"证明相同再删"处理
4. **Windows**（`platform/windows.rs`）：正在被打开的文件不能改名、删除。压缩和解包后删原文件，删不掉就记下来下次再删，不能报错中断收集
5. **版本号**：`kb/mod.rs`、`src/kb/branding.ts`、`src/kb/fixtures.ts` 都要改成 0.8.0
